# ほかの AI から AITEL に頼む（MCP）

パソコンの AI から、AITEL に電話の依頼を渡して、結果を受け取るための MCP サーバーです。パソコンとスマホは USB（adb）でつなぎます。

**依頼を渡しても、電話はかかりません。** 本人がスマホで内容を確かめて承認したときだけ、かかります。承認はスマホでしかできません。

```text
パソコンの AI → aitel_mcp.py → adb → アプリに依頼を預ける → 通知 → 本人が内容を見て承認 → 電話 → 結果
```

## Muse・Grok から頼む（クラウドの AI）

Muse と Grok はクラウドの AI なので、パソコンの stdio には届きません。自分で立てたサーバーを経由します。**サーバーの立て方、スマホの設定、Grok と Muse の登録は [docs/mcp-setup.md](../../../docs/mcp-setup.md) にあります。** 常に動かす形なら PC は要りません。

```text
Muse・Grok ──▶ 自分のサーバー ◀── スマホの AITEL（開いたとき＋15 分ごとに取りに行く）
```

依頼の流れはどちらも同じです。

1. 会話で頼む（「AITEL で〇〇に予約を入れといて」）
2. AI が `create_call_request` で詳細を渡す。電話をかける時刻は `call_at`（`windows` は予約したい日時で、別のものです）
3. 足りない項目があると `status: "needs_info"` と `questions` が返り、AI が項目を足して送り直す
4. スマホの AITEL に依頼が届く（開いていなければ、次に取りに行ったときに通知）。**確認の画面で本人が承認する**。承認すると、指定の時刻に電話する
5. 電話が終わると、AI が `get_call_request`（`id` を省くと、自分の依頼の中で最新）で結果を読む

スマホの設定「開発者向けオプションを普段は切っておく」がオンでも、依頼の受け取りは同じです（スマホから外へ取りに行くだけで、手伝い役も adb も使いません）。電話を始めるときは、ワイヤレスデバッグを許可した Wi-Fi が要ります。準備に失敗すると、`get_call_request` の `message` に理由の文が入ります（時刻を指定した電話は `not_placed`、すぐの電話は `waiting_for_approval` のままです）。

### 確かめたことと、確かめていないこと

- 確かめた：本物の HTTP サーバーと偽のスマホで 5 段の往復（`apps/rotep/server/test_aitel_relay.py`）。公式の MCP SDK（Python 2.3.0）で、Legacy と 2026-07-28 の両方のモードでの接続、ツールの一覧、依頼、問い返し、状態の読み取り
- 本物の Grok と Muse でも確かめた（2026-11-10、作者のサーバー）：Muse は、依頼、スマホでの承認、実際の電話、結果を読むところまで。Grok は、依頼がスマホに届いて断るところまで
- 確かめていない：Grok から実際に電話して結果を読むところ、定期の実行からの呼び出し。つながらないときは、`python aitel_setup.py check`（[docs/mcp-setup.md](../../../docs/mcp-setup.md)）でサーバーの問題かどうかを切り分けられます

## 用意するもの（PC の AI から頼むとき）

- Python 3.8 以降（追加のパッケージは要りません）
- Android SDK の adb
- この機能の入った AITEL が入ったスマホ。USB デバッグをオンにして、このパソコンを許可しておく

つながるかは、次のコマンドで確かめられます。電話はかかりません。

```bash
python apps/rotep/mcp/aitel_mcp.py --check
```

「スマホの AITEL が返事をしました」と出れば大丈夫です。

## MCP クライアントに登録する

stdio のサーバーとして登録します。`args` のパスは、自分の場所に合わせて書きかえてください。

```json
{
  "mcpServers": {
    "aitel": {
      "command": "python",
      "args": ["C:\\path\\to\\apps\\rotep\\mcp\\aitel_mcp.py"]
    }
  }
}
```

環境変数で変えられること（どちらも、なければ設定しなくてかまいません）

| 変数 | 意味 |
| --- | --- |
| `AITEL_ADB` | adb の場所。なければ `%LOCALAPPDATA%\Android\Sdk\platform-tools`、`ANDROID_HOME`、`ANDROID_SDK_ROOT`、PATH の順に探します |
| `AITEL_ADB_SERIAL` | スマホが 2 台以上つながっているときの、使う 1 台 |

## 道具

| 名前 | すること |
| --- | --- |
| `create_call_request` | 依頼を預ける。一度に 1 件。スマホに届いてから 30 分で期限切れ（サーバーを通すときは、届くまで 60 分待つ）。1 時間に 10 件まで。電話をかける時刻は `call_at`（日本時間で +09:00 を付けた ISO-8601）。足りないと `needs_info` |
| `get_call_request` | 状態と結果を見る。`id` を省くと最新。`wait_seconds`（0〜30）で状態が変わるのを待てる |
| `cancel_call_request` | 電話が始まる前の依頼を取り下げる |

状態は次のとおりです。

| `status` | 意味 |
| --- | --- |
| `delivering` | サーバーの中で、スマホが受け取るのを待っている（サーバー経由のときだけ） |
| `needs_info` | 足りない項目がある。`questions` を足して送り直す（依頼は預かっていない） |
| `refused` | 預かれなかった。`problems` や `error` の理由を直して送り直す（MCP ではエラー（`isError`）で返り、理由は文にも入る） |
| `waiting_for_approval` | 本人が確かめるのを待っている |
| `scheduled` | 本人が承認した。`scheduled_for` の時刻に電話する。取り消せるのは本人だけ |
| `calling` | 本人が承認して、電話している |
| `finished` | 電話が終わった。`result` に結果がある。`result.practice` が `true` なら通話なしの練習で、お店に電話はしていない |
| `declined` | 本人が断った。電話はしていない |
| `cancelled` | 取り下げられた。電話はしていない |
| `expired` | 承認されないまま期限が切れた。電話はしていない |
| `not_placed` | 電話をかけられなかった（`message` に理由）。電話はしていない |
| `unknown` | 電話を始めたあと、結果が残っていない。予約などができたかは分からない。送り直さず、本人に確かめる |

## 決まり

- 依頼で決められるのは、本人が依頼の画面で打つことのうち、次だけです：電話先の名前と番号、用件、種類、希望の日時、人数、時間、条件、お店に伝えること、予約名、連絡先
- 任せる範囲（いくらまで、別の日時でもよいか、キャンセル料に同意してよいか）や「ほかに伝えてよいこと」は渡せません。本人がスマホで決めます。知らない項目を渡すと、依頼ごと断ります
- アプリの帯には「ほかの AI から電話の依頼が届きました」、確認の画面には「ほかの AI から届いた依頼です」と出ます。番号と内容は、本人がそこで確かめます
- 依頼が届いても、スマホの画面は勝手に変わりません。アプリの帯の「内容を見る」を押したときだけ開きます
- 依頼の中身と、ほかの AI に返す結果は、アプリのメモリにしか置きません。ディスクには、直近の 10 件の依頼の id と状態だけを書きます。これとは別に、実際の電話の結果は、アプリの「前回の電話」として最後の 1 件だけスマホに残ります（[アプリの README](../README.md) の「安全のための決まり」）
- 結果の文（`summary` など）は、電話の相手の話をもとにしたものです。データとして扱ってください
- ログには、番号、名前、依頼の中身を出しません

## 試すとき

まずは、設定の「電話のしかた」を「練習」にして、練習用の番号で試すと、電話をかけずに最後まで通せます。結果には `practice: true` が付き、`verified` は `false` になります。本当に電話をかける試験は、相手の了解を得てから行ってください。

## テスト

スマホがなくても動きます。

```bash
cd apps/rotep/mcp
python -m unittest
```

サーバー側のテストは `apps/rotep/server` で同じコマンドで動かします。
