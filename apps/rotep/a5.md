# 「電話をかける」で AI の通話を確かめる手順（A5）

> 2026-11-09 12:44 に、協力者との通話で AI の声が相手に届いて、結果の報告まで通りました（direct の方式。そのときは「相手が出た」を手で押しました）。
> そのあと、相手が出たことの読み取りと、端末のマイクを止めることをアプリが行うようになりました。この手順は、その今の動きで書いています。今の動きは、端末ではまだ確かめていません。AITEL の画面のボタンは [a6.md](a6.md) で確かめます。

AI の声を通話の送話に流し、協力者（お店の役）と会話できるかを確かめる手順です。

- 所要時間：40分ほど（協力者との通話は、1回5分以内。うまくいかなければ、もう1回。合格したら、10 節のためにもう1回）
- 設定の「電話のしかた」は「電話をかける」です（開発の段階の名前では L2）。発信はアプリが行います。相手が出たことはアプリが読み取って AI が話し始め、端末のマイクを止めることと電話を切ることもアプリが行います。読み取れないときや止められないときだけ、ボタンと案内が出ます（手順 8、9、13。[README.md](README.md)）

## 1. 何を確かめるか

| 番号 | 確かめること | 見るところ |
| --- | --- | --- |
| 1 | 協力者の側で、AI の声がはっきり聞こえる | 協力者の答え |
| 2 | 会話が最後まで進む（名乗り → 用件 → 結果の報告 → 終話） | 通話中の画面の会話の欄 |
| 3 | 結果が1つ残る | 結果の画面 |
| 4 | 協力者が割り込むと、AI が止まる | 協力者の答えと、数える回数（5 節） |

**合格**：会話が最後まで進み、結果が1つ残り、相手の側で AI の声がはっきり聞こえる。

## 2. 用意するもの

- PC（`adb` が使える。ログと 10 節のコマンドに使う）と、Nothing Phone (2a)
- アプリ（APK）。手伝い役の起動は、[diagnostics.md](diagnostics.md) の起動のしかたのとおりに行う
- Gemini の API キー（有料枠）。設定の画面に貼って保存する
- 協力者1人（予備1人）。会話できる人で、静かな場所にいて、**イヤホンを使う**（AI の声が協力者のスピーカーから回り込んで、AI 自身に聞こえるのを防ぐ）
- 協力者には、**先に次を伝えて、同意をもらいます**
  - 目的：AI が電話で予約の会話をできるかの確認であること。AI は、最初に AI だと名乗る
  - 協力者の声が、Google の Gemini（有料枠）に送られて処理されること
  - 協力者の言葉の文字起こしが、Anthropic の Claude にも送られて処理されること（設定の「通話の考える役に Claude を使う」がオンのとき。既定でオンです）
  - こちらでは録音を残さないこと。協力者の側も録音しない。メモは、確かめたら消してもらう
  - 協力者は、お店の人の役をすること（5 節の 3 つをお願いする）
- 協力者の電話の番号は、アプリの依頼の画面にだけ入れます。この資料にも、記録にも、書きません

## 3. 守ること

- 電話をかける相手は、同意した協力者だけです。お店や会社には、かけません。緊急の番号では試しません
- 通話の音声は、保存しません。画面の会話の文は、この画面にだけ出ます。記録には、会話の中身も、名前も、番号も書きません
- 検証の間、Wi-Fi 通話はオフ。VoLTE で通話します。Bluetooth やヘッドセットは外します
- 通話の上限の時間（委任ポリシーの `maxCallSeconds`）になると、AI は止まり、本人に代わります。このときはご自分で話してください

## 4. 手順

### 4-1. 通話の前

1. アプリを入れ、手伝い役を起動します（[diagnostics.md](diagnostics.md) の起動のしかた）。診断の画面（設定の「困ったとき」の「診断の画面を開く」から開きます）の「2. 手伝い役の状態」が「動いている」になり、`uid=2000` と出ることを確かめます。**手伝い役が動いていないと、確認の画面に「手伝い役が動いていません。…」と出て、電話をかけられません**（音の出ない電話を、かけてしまわないため）
2. 診断の画面の「3. 環境の報告」で「報告を取る」を押し、コピーして記録に貼ります（通話の前）
3. アプリの設定を開き、次を選びます
   - 「電話のしかた」：「電話をかける」
   - 「困ったとき」の「端末のマイクを止めない」：オフ（AI の声が相手に届かないときだけオン。そのときは静かな部屋で行い、AI が話す間は本人は話さない）
   - 「通話の音をこの端末で鳴らす」：**1回目はオン**（AI に相手の声が届くかの基準）。1回目に合格したら、**2回目はオフ**（既定の形）で、10 節を確かめる
   - API キーが「保存済み」になっていること
4. 協力者に、2 節の説明をして、同意をもらいます

### 4-2. 依頼と承認

5. ⋮ の「手で入力する」のフォームに入れます（協力者の番号を会話に書かないため）
   - 店名：架空の名前（実在のお店の名前は入れない）
   - 電話番号：**協力者の番号**（ここだけに入れる）
   - 用件、希望の日時と幅、人数と幅、予約名（架空）、連絡先（架空）
   - 伝えてよいこと、任せる範囲：委任ポリシーの既定のままでよい
6. 「確認へ」を押し、確認の画面で内容を見ます（**「お店を調べる」は押しません**。協力者の番号が Google に送られるため）。「電話のしかた：電話をかける」と出ていることを確かめて、問題がなければ「承認して電話する」を押します（マイクと通知の許可を求められたら許可する）
7. アプリが発信します。協力者の電話が鳴ります

### 4-3. 会話

8. 協力者が出ると、**何も押さなくても** AI が話し始めます（アプリが読み取ります）。読み取れないときは「相手が出た」が出るので、**電話がつながったあとで**押します（つながる前に押すと、AI の声を通話に流せません）
9. 端末のマイクはアプリが止めます（通話の画面のボタンが「マイクを戻す」になっていれば止まっています）。止められなかったときだけ、「電話の画面で、端末のマイクを止めてください」と案内が出るので、電話の画面のミュートで止めます。「端末のマイクを止めない」がオンのときは、アプリは止めません。そのときは**ミュートを入れず、電話の画面のミュートが外れていることを確かめます**（いつもの癖で押すと、AI の声が届きません）
10. AI が、AI だと名乗って話し始めます。話し始めるまでの時間は、画面には出ません。通話の前から PC で `adb logcat -s Rotep/call` を流しておき、`first agent audio … ms after answered` の行を見ます（端末のログはすぐ消えるので、通話のあとでは残っていないことがあります）。**この値を記録します**
11. 協力者は、お店の人の役で答えます。5 節の 3 つを、会話の中で行ってもらいます
12. 会話を見ながら、5 節の回数を数えます。画面を見るのは本人、聞こえ方を言うのは協力者です
13. AI が結果を報告して終わると、アプリが電話を切ります（「電話を切っています」と出ます）。切れないときだけ、電話の画面で通話を切って「切った」を押すよう案内が出ます
14. 結果の画面が出ることを確かめます。結果の欄が1つであることを見ます

### 4-4. 終わらせる

**1回目（「通話の音」オン）に合格したら**、ここで設定をオフにして手順 5 に戻り、10 節を確かめます（手伝い役はそのままです）。

15. 電話の画面で、**マイクのミュートが外れていることを確かめます**（アプリが止めたマイクは、通話が終わると戻ります。手で止めたときは、手で戻します）
16. 診断の画面で「報告を取る」を押し、コピーして記録に貼ります（通話のあと）
17. 手伝い役を終わらせ、残っていないことを確かめます（[diagnostics.md](diagnostics.md) の終わらせ方のとおり）
18. 協力者に、メモなどの記録を消してもらいます

## 5. 協力者にお願いする3つと、数えること

| お願い | 見ること | 数える |
| --- | --- | --- |
| 1. 普通に答える（AI の質問に、短く答える） | AI の声がはっきり聞こえるか。会話が進むか | ― |
| 2. AI が話している途中で、1回、わざと割り込む（「あ、ちょっと待ってください」と言う） | AI がすぐ止まるか | 割り込んだのに止まらなかった回数 |
| 3. 予約の範囲で表せないことを、1つ聞くか、提案する（例：別の時間を勧める、席の種類を聞く） | AI が勝手に決めず、断るか、本人に代わるか | 委任ポリシーで表せなかった質問や提案（下の記録） |

- **割り込んだのに止まらなかった回数**：協力者が話したのに、AI が話し続けた回数
- **相手が話していないのに止まった回数**：協力者が黙っているのに、AI が話すのをやめた回数（回り込みや雑音の疑い）

## 6. 記録すること

手元の記録にだけ置きます（リポジトリには書きません）。電話番号、名前、会話の中身は書きません。

| 項目 | 内容 |
| --- | --- |
| 条件 | 日時、Android の版とビルド（報告に出る）、VoLTE で通話したか、Wi-Fi 通話がオフか、通話の音の設定（オン／オフ）、「端末のマイクを止めない」の設定（オン／オフ）、マイクが止まっていたか、相手が出たことをアプリが読み取ったか（「相手が出た」を押したか）、協力者がイヤホンを使ったか |
| 手伝い役 | 起動のしかた、pid と uid、通話の前と後の環境の報告 |
| AI が話し始めるまでの時間 | ログの `first agent audio … ms after answered` の値（手順 10） |
| 接続が続いた時間 | AI の接続が切れるまで（またはこの通話が終わるまで）の、通話中の画面の経過時間 |
| GoAway | 「まもなく AI との接続が切れます」が出たか。出たなら、そのときの経過時間 |
| 割り込み | 割り込んだのに止まらなかった回数。相手が話していないのに止まった回数 |
| 委任ポリシーで表せなかった、お店の質問や提案 | 短い言い換えで書く（例：「席の種類を聞かれた」）。名前、番号は書かない |
| 聞こえ方 | 協力者の答え：AI の声がはっきり聞こえたか（はっきり／小さい／とぎれる／聞こえない）、遅れの感じ |
| 結果 | 結果の画面の状態、結果が1つか。終わり方（AI が切った・協力者が切った・上限・本人に代わった・通話の音声が止まった） |
| 通話の音声の出来事 | 診断の画面の「出来事」の欄（「音声の通り道が動き始めた」「…が終わった」「…が失敗した」の行） |

## 7. 結果の判断

| 結果 | 判断 |
| --- | --- |
| 会話が最後まで進み、結果が1つ残り、AI の声がはっきり聞こえた | A5 に合格。割り込みの回数と、表せなかった質問や提案は、次の直しの材料にする |
| 会話は進んだが、AI の声が小さい・とぎれる | 音量と遅れを記録する。A3 の記録（出力先、音量）と比べる。もう1回試す |
| AI の声は聞こえるが、割り込んでも止まらない | 回数を記録する。AI の声が回り込んでいないか、受話の音量（診断の画面の「4. 受話の音量」）を同時に見て確かめる |
| AI の声が相手に届かない | 6 節の出来事と、下の表を見て、直せる原因が見えたらもう1回。見えなければ、[a3.md](a3.md) の試験でどの方式なら届くかを確かめる。設定の「困ったとき」の「端末のマイクを止めない」も試す |
| 結果が残らない／2つ残る | 画面の状態と出来事を記録する。これは直す対象 |

10 節（通話の音を消す形）がだめなときは、設定「通話の音をこの端末で鳴らす」をオンにして使います。

## 8. うまくいかないとき

画面に出る文は、そのまま記録に貼ります（電話番号と名前は入っていません）。

| 症状（画面の文） | 見当 | すること |
| --- | --- | --- |
| 確認の画面に「手伝い役が動いていません。…」 | 手伝い役が動いていない（または、つながっていない） | [diagnostics.md](diagnostics.md) の起動のしかたで起動し、診断の画面で「動いている」を確かめてから、確認の画面に入り直す |
| 「通話の音声を使えません（通話中ではない…）」 | 「相手が出た」を、電話がつながる前に押した。または通話がもう終わっている | 電話がつながってから「相手が出た」を押す |
| 「通話の音声を使えません（手伝い役が動いていないか、別の通話の音声を扱っています）」 | 手伝い役が止まっている。または前の通話の音声の処理が残っている | [diagnostics.md](diagnostics.md) の起動のしかたで起動し直す。診断の画面の状態を見る |
| 「通話の音声を使えません（受話を取れなかった…）」 | 受話の取得に失敗 | 診断の画面の「4. 受話の音量」で、受話が取れるかを先に確かめる（H） |
| 「通話の音声を使えません（送話を作れなかった…）」 | 通話用の出力がない、権限が足りない、通話中でない | 例外の文を記録する。[a3.md](a3.md) の試験1 で届くかを見る |
| 「録音が止められました…」 | システムが受話の録音を黙らせた（`isClientSilenced`） | 診断の画面の報告の「録音の名義」の行と、黄色の帯を記録する |
| 「手伝い役が止まりました」 | 手伝い役のプロセスが終わった | 診断の画面の「出来事」を記録して、起動し直す |
| 「通話の音声が止まりました（通話が終わった…）」 | 通話が終わった、または手伝い役が止めた | どちらが先に切ったかを記録する |
| AI は話しているが、協力者に聞こえない | ミュートの状態が違う、または送話がこの通話で動いていない | 電話の画面のミュートを確かめる。「困ったとき」の「端末のマイクを止めない」を試す。[a3.md](a3.md) の試験で確かめる |
| AI が、自分の声で止まる | 協力者の側のスピーカーから、AI の声が回り込んでいる | 協力者にイヤホンを使ってもらう。もう1回試す |
| AI が話し始めるまでの時間が長い | 接続、または手伝い役の起動が遅い | 秒数を記録する。手伝い役を先に起動しておく |

ログを取るときは、PC で次を実行してから、操作します。止めるときは Ctrl+C です。

```bash
adb logcat -s RotepDiag:V RotepHelper:V
```

ログに電話番号や名前は出ません。出ていたら、貼らずに知らせてください。

## 10. 通話の音を消す形（既定）を確かめる

設定の「通話の音をこの端末で鳴らす」がオフのとき、AI が話している間、端末から通話の音を出しません（手伝い役が STREAM_VOICE_CALL を消音します。相手が出て 1.5 秒ほどあとに消えます）。**消音で、AI に届く相手の声まで消えないか**は、端末の音声の部品しだいで、ソースからは分かりません。ほかの端末では、受話がほぼ無音になった、読めなくなって通話が切れた、という報告があります。ここで確かめます。

| 確かめること | 見方 | 期待すること |
| --- | --- | --- |
| 端末から音が出ない | 相手が出て 3 秒たったら、受話口に耳を当てる | お店の役の声も AI の声も聞こえない |
| AI に相手の声が届く | 協力者の問いかけに AI が答えるか | 1回目（オン）と同じように会話が進む |
| AI の声が相手に届く | 協力者に聞く | 1回目と同じように聞こえる |
| 音で知らせて戻る | 通話中に「AI を止めて本人に代わる」を押す | **知らせの音が聞こえ、端末が振動して通知が出て**、そのあと相手の声も聞こえる |
| 机に置いていても気づく | 端末を机に置いたまま、もう1回「AI を止めて本人に代わる」を押す | 振動と通知で気づける |
| 通話の音が戻った | 通話を切った直後、次の発信の前に、下のコマンドを実行する | `Muted: false`。通話の前に控えた音量の段と同じ |
| アプリが落ちたとき | 協力者との通話の消音中に、下の force-stop を実行する | 手伝い役が音を戻す（相手の声が聞こえる） |
| 手伝い役が落ちたとき | 協力者との通話の消音中に、下の kill を実行する | アプリが音を戻す（相手の声が聞こえる）。戻らなければ通話中に音量の＋ |

```bash
adb shell "dumpsys audio | grep -A1 '^- STREAM_VOICE_CALL'"
```

```bash
adb shell am force-stop io.github.incallagent.rotep
```

```bash
adb shell pidof rotep-helper
```

出た番号を使って `adb shell kill <pid>` を実行します。

（「普通に発信して聞こえる」では確かめになりません。Android が発信のときに消音を解くので、消音が残っていても聞こえてしまいます。）

うまくいかないとき：

- **消音のあと AI が相手に反応しない**：この端末では、消音で受話の取得も無音になっているおそれがあります。ログに `call quiet: the downlink went silent` と出ていれば、アプリが自分で音を戻しています。設定をオンにして使い、知らせてください
- **消音のあと AI の声が相手に届かない**：消音が送話も消している見込みです（自動の歯止めでは見つけられません）。設定をオンに戻し、記録して知らせてください
- **消音のあと通話が切れた**：設定をオンに戻し、切れるまでの秒数を記録して知らせてください
- **端末から音が消えない**：`adb logcat -d -s RotepHelper:V` の `call quiet:` の行を全部記録して知らせてください（聞こえるだけなので、通話は続けて構いません）
- **通話のあとも相手の声が聞こえない**：通話中に音量の＋を押すと戻ります（通話の外の＋は別の音量を動かします）。手伝い役とアプリの両方が落ちたときは、アプリを開き直すと、戻そうとします
