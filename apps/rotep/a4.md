# A4：「全自動で電話をかける」（L3）を確かめる

本人が Nothing Phone (2a) で行う手順です。通らなければ「電話をかける」のまま練習します。

L3 では、アプリが自分でかけた1本を、画面のない InCallService（`RotepInCallService`）で操作します。Telecom がこのサービスにつなぐのは、`MANAGE_ONGOING_CALLS` の AppOps が許可されていて、サービスが有効なときだけです。サービスはふだん無効で、アプリが AI の通話をかける直前に有効にし、通話が終わったら無効に戻します。

> 2026-11-09 21:51 に、協力者との電話で 1 回通りました（3 節の表の 1、2 と、5 の「AI が結果を報告して電話を切る」まで）。相手が出てから AI が話し始めるまでは約 2.5 秒でした。3 のミュート、4 のプッシュ音、6 の保留、7 のほかの通話、通話の画面のスピーカーとキーパッド（[a6.md](a6.md)）は、まだ確かめていません。同じ電話で読み間違いなどの問題が見つかって、直している最中です（[README.md](README.md) の「いまの状態」）。

## 前に要るもの

- 「電話をかける」で AI の通話（A5）が一度通っていること（2026-11-09 に通った。このときは「相手が出た」を手で押した）
- 相手役は、目的を説明して同意をもらった協力者。説明することは、目的、AI の声が流れること、相手の声が Gemini に送られること、録音を残さないこと。声は Gemini、考えるのは Claude の形（既定）では、相手の言葉の文字起こしが Claude に送られることも説明する
- プッシュ音は、協力者に「ピッ」が聞こえたかを答えてもらって確かめる。留守番電話の操作用の番号（1417 など）は短い番号なので、アプリが断る（`DialCheck`。安全の決まりは緩めない）
- お店、会社、時報、緊急の番号にはかけない
- PC の adb は1つだけ使う。アプリは手元のビルドを入れておく（`adb install -r apps/rotep/build/outputs/apk/debug/rotep-debug.apk`）

## 1. AppOps を許可する

PC なしの形で手伝い役を起動しているときは、診断の画面（設定の「困ったとき」の「診断の画面を開く」から開きます）の「PC なしの起動」の「全自動を許可」を 1 度押します（下の `appops set` と同じです）。「全自動の許可が入りました」と出れば入っています。このボタンは、スマホでは、まだ確かめていません。

PC から行うときは、次のとおりです。

```bash
adb shell appops set io.github.incallagent.rotep MANAGE_ONGOING_CALLS allow
```

```bash
adb shell appops get io.github.incallagent.rotep MANAGE_ONGOING_CALLS
```

- `MANAGE_ONGOING_CALLS: allow` と出れば許可されている。`pm grant` では付かない
- **この許可は再起動しても残る。`appops reset` でも消えない**（この操作は reset の対象外）。後片付けで必ず `default` に戻す（5）
- 許可している間も、サービスはふだん無効なので、普段の通話にはつながらない。アプリが通話の途中で止まって有効のまま残ったときは、次の通話でサービスがつながりを断り、自分で無効に戻る

## 2. アプリを用意する

1. 設定 → 電話のしかた：「全自動で電話をかける」。許可がないときは、その下に「全自動で電話をかける許可がありません」と出るので、1 をやり直す。AI の声が相手に届かないことがあったときだけ、「困ったとき」の「端末のマイクを止めない」をオンにする（オフのときは、アプリが Telecom で端末のマイクを止める）
2. 設定 → 「通話の音をこの端末で鳴らす」：オフ（A5 の 10 節がだめだったときはオン）
3. 依頼（「手で入力する」） → 「練習用の例を入れる」 → 電話番号を相手役の番号に直す → 「確認へ」
4. 確認の画面に「電話のしかた：全自動で電話をかける」と出ることを確かめる（**「お店を調べる」は押さない**。相手役の番号が Google に送られるため）
5. 「承認して電話する」。電話の許可を求められたら許可する（ほかの通話の途中かを確かめるため `READ_PHONE_STATE` も使う）

協力者には、次のように話してもらう：電話に出る → AI の名乗りを聞く → 最初に「ご予約の方は 1 を押してください」と言う → 「ピッ」が聞こえたかを、聞こえた・聞こえないで答える → 店員の役で予約の会話をする → 「では、それでお待ちしています」などで締める。

## 3. 試す

| 番号 | 確かめること | 見るところ | 期待すること |
| --- | --- | --- | --- |
| 1 | アプリがかけた1本を見つける | 通話中の画面 | 発信から数秒で「相手が出るのを待っています」になる。**発信の直前に有効にしたサービスに Telecom がつないだことの確かめ**。20 秒たって、音で知らせて「発信はしましたが、アプリから通話を操作できません」と出たら不合格（お店の役の電話は鳴ったままなので、電話の画面で切る。4 で切り分ける） |
| 2 | 相手が出たこと | 通話中の画面、協力者 | 協力者が出ると「AI が会話しています」になり、AI が名乗る |
| 3 | ミュート | 電話の画面 | 「端末のマイクを止めない」がオフ（既定）：AI が話している間、電話の画面でミュートが入っている。小さく「テスト」と言い、協力者に聞こえないことを確かめる。オン：ミュートは**入っていない**。協力者に AI の声が届いていることを確かめる。本人は話さない |
| 4 | プッシュ音 | 通話中の画面、協力者の答え | 協力者の「1 を押してください」で、画面に「プッシュ音：1」と出る。協力者が「ピッが聞こえた」と答える |
| 5 | 終話 | 結果の画面、電話の画面 | AI が結果を報告して電話を切る。結果の画面が出て、電話の画面でも通話が終わっている。電話の画面でミュートが外れている |
| 6（できれば） | 保留 | 通話中の画面 | 2本目をかけ、AI が話している途中で電話の画面の「保留」を押す。「保留になりました」で AI が止まり、音で知らせ、ミュートが外れる。保留を解いて自分で話し、自分で切る |
| 7（できれば） | ほかの通話 | 通話中の画面 | 2本目で、別の協力者から電話をかけてもらう。鳴っているだけでは AI は続ける。出ると、こちらの通話が保留になり、AI が止まる |

- 通話の音がオフのときは、相手が出て 3 秒たったら端末から通話の音が出ないことも見る。5〜7 で AI が止まるときは、知らせの音・振動・通知があり、そのあと相手の声が聞こえること
- 1 本の通話で 1〜5 をまとめて確かめられる。1 回で通らなければ、直してからもう1回だけ試す
- 3 のミュートを診断の報告でも確かめるときは、4 のプッシュ音を見たあと、AI が会話している間に、上の「設定」の「困ったとき」の「診断の画面を開く」で診断の画面を開き、「3. 環境の報告」の「報告を取る」を押す（「端末のマイクを止めない」がオフなら「マイクのミュート: はい」、オンなら「いいえ」）。最近使ったアプリからアプリに戻り、設定の「戻る」で通話中の画面に戻る。通話の前やあとに取ると、どちらでも「いいえ」になるので確かめにならない
- プッシュ音を AI が押さなかったときは、3 の記録に「AI が押さなかった」と書く（通話の操作の不具合とは分ける）

## 4. つながらないときの切り分け

通話のあとすぐ、PC で：

```bash
adb shell "logcat -d | grep -iE 'Skipping binding|rotep'"
```

| 出ている行 | 意味 | すること |
| --- | --- | --- |
| `Skipping binding to io.github.incallagent.rotep:...RotepInCallService` | Telecom が AppOps の許可を見ていない | 1 の `appops get` を確かめる。`allow` なのにこの行が出るなら、この端末ではこの方法が使えない。「電話をかける」のまま |
| `found:ComponentInfo{io.github.incallagent.rotep/...RotepInCallService} isRequestedtype:true isEnabled:false` | 発信の直前に有効にしたのが、Telecom の問い合わせに間に合わなかった | 記録して知らせる |
| `isRequestedtype:true isEnabled:true` があるが、`Rotep/incall` の `bound` がない | Telecom はつなごうとしたが、届いていない | 記録して知らせる |
| `Rotep/incall` の `bound` と `added call#…` がある | つながったが、かけた1本と見分けられなかった | 記録して知らせる |

通話中なら、つながっているかを次でも見られる（`RotepInCallService` の行に `connected, bound` があればつながっている）：

```bash
adb shell "dumpsys telecom | grep -i rotep"
```

ログや dumpsys には電話番号が出ることがある。手元にだけ置き、リポジトリ・PR・チャットに貼らない。

## 5. 後片付け（試したあと毎回）

1. AppOps を元に戻す（PC の adb から行います。アプリの画面には、戻すボタンはありません）

   ```bash
   adb shell appops set io.github.incallagent.rotep MANAGE_ONGOING_CALLS default
   ```

   ```bash
   adb shell appops get io.github.incallagent.rotep MANAGE_ONGOING_CALLS
   ```

   `allow` と出なければよい（`default` か `No operations.`）

2. サービスが無効に戻っていることを確かめる。次の一覧に `io.github.incallagent.rotep` が出なければよい

   ```bash
   adb shell "cmd package query-services --components -a android.telecom.InCallService"
   ```

   出たときは、manifest の既定（無効）に戻す（アプリが開いていれば閉じられる）

   ```bash
   adb shell pm default-state io.github.incallagent.rotep/.service.RotepInCallService
   ```

3. 通話が全部終わってから5秒ほど待ち、アプリがつながったままになっていないことを確かめる。何も出なければよい

   ```bash
   adb shell "dumpsys telecom | grep -i rotep"
   ```

4. 電話の画面でミュートが外れていることを確かめる（ミュートは端末全体に効く）
5. 次の発信の前に、通話の音が戻っていることを確かめる（`adb shell "dumpsys audio | grep -A1 '^- STREAM_VOICE_CALL'"` で `Muted: false`。発信すると Android が解くので、発信のあとでは確かめにならない）
6. アプリを入れたまま（動かさずに）、普通の発信と着信を1回ずつ行う。相手に声が届き、着信が鳴ること
7. 残りの後片付け：Wi-Fi 通話を戻す、USB デバッグの許可の取り消し、相手の側の記録を消す、手元の記録に番号や名前がないか

## 6. 合格（G4）と記録

合格：3 の 1〜5 が期待どおり。通話のあと通話の音が戻っている。5 の後片付けのあと、普通の発信・着信に問題がない。`dumpsys telecom` で、アプリがつながったままになっていない。

記録すること（番号と名前は書かない）：

- 1〜7 の結果。発信から「相手が出るのを待っています」までの秒数
- 発信の直前に有効にしたサービスに Telecom がつないだか（4 の表のどれだったか）
- 端末の条件：Android とビルド番号、VoLTE か、「端末のマイクを止めない」の設定

公式に案内された一般向けの方法ではないので、OS の更新が入ったら、この A4 をやり直す。
