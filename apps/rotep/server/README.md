# AITEL の窓口サーバー

Muse や Grok から AITEL に予約の電話を頼むための、郵便受けのサーバーです（ADR-042）。自分で立てて、自分だけで使います。

**立て方は [docs/mcp-setup.md](../../../docs/mcp-setup.md) にあります。** 上から順に進めれば、スマホの設定、Grok と Muse の登録、試し方まで終わります。ここには、作りと決まりだけを書きます。

```text
Muse・Grok ──HTTPS（トークン）──▶ このサーバー（メモリだけ）◀──HTTPS（アプリから外へ）── AITEL アプリ
```

- 電話はスマホのアプリがかけます。このサーバーは電話をかけられません。依頼はスマホの確認の画面で本人が承認するまで、電話になりません
- 依頼の中身と結果はメモリだけに置きます。ディスクに書かず、ログにも出しません。サーバーを再起動すると消えます
- AI のキーはここに置きません

## ファイル

| ファイル | すること |
| --- | --- |
| `aitel_relay.py` | サーバーの本体。`../mcp/aitel_mcp.py` か、同じフォルダの `aitel_mcp.py` を使う |
| `aitel_setup.py` | トークンを作る、サーバーを動かす、確かめる、Linux の常用の形に置く。`python aitel_setup.py --help` |
| `relay.env` | `aitel_setup.py init` が作る設定のファイル。本人だけが読める。リポジトリに入れない |
| `Dockerfile` | Cloud Run で動かすときのコンテナ。`aitel_relay.py` と `aitel_mcp.py` と同じフォルダに置いてビルドする（手順は docs/mcp-setup.md の C） |

## 環境変数

`relay.env` に書きます。`aitel_setup.py` が書くのは上の 3 つだけで、ほかは要るときに足します。変えたら、サーバーを動かし直します。

| 変数 | 意味 |
| --- | --- |
| `AITEL_PUBLIC_URL` | 外から届く `https://` の URL。最後に `/mcp` は付けない |
| `AITEL_AI_TOKEN` | Muse・Grok のトークン。32 文字以上 |
| `AITEL_PHONE_TOKEN` | スマホのトークン。AI 用とは別の値で 32 文字以上 |
| `AITEL_RELAY_HOST`、`AITEL_RELAY_PORT` | 待ち受ける場所。既定は `127.0.0.1` と `8787` |
| `AITEL_OAUTH_REDIRECT_HOSTS` | Grok の許可の画面の宛先に足すホスト（カンマ区切り）。`grok.com`、`x.ai`、`www.cursor.com`（Grok のカスタムコネクタの戻り先）は最初から許可 |
| `AITEL_RELAY_ALLOWED_ORIGINS` | ブラウザから呼ばれるときに許可する Origin（カンマ区切り） |

## 決まり

- サーバーは依頼の項目を足さず、訳しません。検査はスマホの `PhoneRequestHandler.handle` でします（緊急番号・有料番号、数の制限、期限など）
- 依頼：未配達は 60 分、承認待ちはスマホが受け取ってから 30 分で期限切れ。終わった依頼と結果はメモリで 24 時間
- スマホのプロセスが変わると、承認待ちの依頼をもう一度配ります（プロセスが死んで消えた依頼が戻るように）
- スマホが受け取ったのに返事をしない命令は、返事が来るか依頼が終わるまで、20 秒ごとに配り直します（応答が途中で失われても届くように）。スマホは同じ id を同じ依頼として扱います。配り直しは新しい版のアプリが前提なので、サーバーとアプリは一緒に更新します
- スマホが受け取った依頼を AI が取り下げると、スマホにも取り下げを送ります。スマホで本人がもう承認していたら、取り下げられません
- スマホが状態を知らせないまま時間が過ぎると（プロセスが死んだなど）、`calling` は 60 分、`scheduled` は指定の時刻の 60 分あとで `unknown` になります。`unknown` のときは送り直さず、本人に確かめてください
- 認証は、AI 用のトークン（または Grok の OAuth）と端末用のトークンで分かれています。AI 用のトークンで `/phone/*` は通らず、端末用のトークンで `/mcp` は通りません
- AI 用のトークンを変えると、OAuth で渡したアクセストークンは全部無効になります
- Grok と Muse は、互いの依頼を読むことも取り下げることもできません。ほかの AI の依頼は「残っていません」と同じ答えになり、busy のときも id は返しません。AI 用のトークンで直接呼ぶと、すべて見えます。どの AI かは許可（OAuth）のときに決まるので、この機能より前に発行したトークンは、つなぎ直すまで全部見えます。サーバーを再起動したあとにスマホの報告で思い出した依頼は、どの AI からでも読めます（サーバーのテストで確かめました。本物の Grok と Muse でも、もう一方の AI には依頼の中身が渡らず、busy の文だけが返ることを確かめました。電話なし、2026-11-10）
- `/openapi.json` はトークンなしで読めます。中身は道具の説明と公開の URL だけです
- 本文は `Content-Length` のほか、`Transfer-Encoding: chunked` でも受けます（前段のプロキシが変えることがあるため）。どちらも上限は 64 KiB です。両方が付いた依頼は断ります

```bash
cd apps/rotep/server
python -m unittest
```
