# 送話の試験の手順

診断の画面（設定の「困ったとき」の「診断の画面を開く」から開きます）の「5. 送話の試験」で、目印の音が通話の相手に届くかを確かめる手順です。手伝い役の確認（[diagnostics.md](diagnostics.md)）に合格してから行います。

> 2026-11-09 の協力者との通話（A5）で、direct の方式で AI の声が相手に届きました。設定の「電話をかける」と「全自動で電話をかける」は direct だけを使います。redirection とスピーカーは設定から外しました（この画面の試験では残っています）。目印の音の試験そのものは、まだ行っていません。

- 所要時間：30分ほど（協力者との通話は15〜20分）

## 1. 何を確かめるか

| 試験 | 方式 | Nothing のマイク | 確かめること |
| --- | --- | --- | --- |
| 0 | 注入しない。試験2 と同じ設定と音量で、出力先を指定せずに鳴らす（通話中は受話口から鳴る） | ミュートしない | 回り込みだけで、相手の側でどのくらいの大きさに聞こえるか（比べるための基準） |
| 1 | direct：出力先を `TYPE_TELEPHONY` にして鳴らす | 電話の画面でミュート | 目印の音が、相手の側で2回とも聞き取れるか。**これが合否を決める** |
| 2 | direct | ミュートしない | 試験0・1 と比べる |
| 3 | redirection：`getCallUplinkInjectionAudioTrack` | 電話の画面でミュート | 試験1 と同じ。**2回まで。通話が切れたら、それ以上しない** |
| 4 | 注入しない。通話をスピーカーにし、端末のスピーカーで鳴らす | ミュートしない | 相手の側で2回とも聞き取れるか（スピーカーで流す形の候補） |

合格の条件：Nothing のマイクを止めた状態で、目印の音が、相手の側で2回とも聞き取れる。

### 目印の音

- 高さの違う3つの音（880・1320・1760 Hz）を1秒ずつ、合わせて3秒。そのあと7秒は無音。10秒ごとにくり返します
- 鳴らす秒数の既定は20秒です。**1回の試験で、目印の音は2回（始めてから0秒と10秒）鳴ります**。20秒で自動で止まります
- 音量の既定は -12 dBFS（ピーク）で、小さめです。聞こえないときだけ -6 にします

## 2. 用意するもの

- 手伝い役の確認に合格した版のアプリと、PC（`adb` が使える）
- **手伝い役の起動は、[diagnostics.md](diagnostics.md) の起動のしかたのとおりに行います**
- 協力者1人（予備1人）。その場で「聞こえた／聞こえない」と、聞こえたときのことを言ってもらうので、会話できる人にします
- 協力者には、**先に次を伝えて、同意をもらいます**
  - 目的：AI の声が電話の相手に届くかの確認であること（今日は AI の声の代わりに、目印の音を使う）
  - 目印の音（高さの違う3つの音）が、電話で何回か流れること
  - 録音しないこと。こちらでは音を保存しない。協力者の側も録音しない。メモは確かめたら消してもらう
- 協力者の電話の番号は、この資料にも、記録にも、書きません

## 3. 守ること

- 電話をかける相手は、同意した協力者だけです。お店や会社には、かけません。緊急の番号では試しません。緊急通報が要りそうなときは、試しません
- 通話の音声は、保存しません。画面の記録には、電話番号も名前も入りません。コピーして記録に貼ってかまいません
- 検証の間、Wi-Fi 通話はオフ。VoLTE で通話します。Bluetooth やヘッドセットは外します
- 試験3 は2回までです。通話が切れたら、それ以上しません
- 端末の出力のミュート（音量を0にするなど）は、試しません

## 4. 手順

### 4-1. 通話の前

1. [diagnostics.md](diagnostics.md) の起動のしかたで、手伝い役を起動します（PC から `adb shell sh /data/local/tmp/rotep-helper.sh`。スクリプトを端末に置く `adb push` は最初の1回だけ。PC なしのときは同じ文書の 9 節）。「2. 手伝い役の状態」が「動いている」になり、`uid=2000` と出ることを確かめます
2. 「3. 環境の報告」の「報告を取る」を押し、コピーして記録に貼ります（通話の前）
3. 「5. 送話の試験」の設定を確かめます：遅らせる 0 秒、鳴らす 20 秒、音量 -12

### 4-2. 協力者に電話する

4. 協力者に、普通の電話のアプリで電話します。スピーカーにしません
5. 協力者に伝えます：「これから、高さの違う3つの音を流す。1回の試験で2回、10秒あけて流れる。聞こえたら、そのたびに『聞こえた』と言ってほしい。大きさ（はっきり／小さい／聞こえない）も教えてほしい」
6. 診断の画面に戻り、「報告を取る」を押して、コピーし、記録に貼ります（通話中）。次を見ます

   | 行 | 見ること |
   | --- | --- |
   | 音声のモード | `MODE_IN_CALL (2)`。これでないと、試験1〜3 は始まりません |
   | `TYPE_TELEPHONY(18)` の出力 | あるか、ないか（試験1・2 に要る） |
   | `isPstnCallAudioInterceptable` | 値（試験3 に要る） |

### 4-3. 試験（0 → 1 → 2 → 4 → 3 の順）

試験3 は通話が切れることがあるので、最後にします。端末は机に置き、試験0・1・2 の間は置き方を変えません。

手順 7 では、下の表の順に、試験ごとに (1)〜(5) を行います。

7. 試験ごとに、次を行います
   - (1) 「試験」で番号を選びます。その下に出る「始める前に」のとおりに、電話の画面のミュートとスピーカーを合わせます
   - (2) 協力者に「いまから流す」と言います。**試験1・3 はミュートにすると、こちらの声が届きません。ミュートにする前に言っておきます**（協力者の声は、ミュートの間も聞こえます）
   - (3) 「開始」を押します。20秒で自動で止まります。途中で止めたいときは「止める」を押します
   - (4) 協力者の答えをメモします：1回目と2回目が聞こえたか、大きさ
   - (5) 「記録」の欄で、止まった理由と、出力先 `getRoutedDevice()` の行を見ます

| 順 | 試験 | 電話の画面 | 気をつけること |
| --- | --- | --- | --- |
| 1 | 0 | ミュートしない。スピーカーにしない | 受話口から小さく鳴ります。相手に回り込んで聞こえる大きさの基準です |
| 2 | 1 | マイクをミュート | 合否を決める試験です |
| 3 | 2 | ミュートを戻す | 試験0・1 と大きさを比べてもらいます |
| 4 | 4 | スピーカーにする。ミュートしない | **スピーカーにしてから「開始」を押します**。終わったらスピーカーを切ります |
| 5 | 3 | マイクをミュート | 2回まで。通話が切れたら、それ以上しません。切れたかは、電話の画面を目で見て記録します |

### 4-4. 終わらせる

8. 電話の画面で、**マイクのミュートを戻し、スピーカーを切ります**。通話を切ります
9. 「記録をコピー」を押し、記録に貼ります（この画面で行った試験の記録が、まとめてコピーされます）
10. 手伝い役を終わらせ、残っていないことを確かめます（[diagnostics.md](diagnostics.md) の終わらせ方のとおり）
11. 協力者に、メモなどの記録を消してもらいます

## 5. 記録すること

手元の記録にだけ置きます（リポジトリには書きません）。電話番号と名前は書きません。

| 項目 | 内容 |
| --- | --- |
| 条件 | 日時、Android の版とビルド（報告に出る）、VoLTE で通話したか、Wi-Fi 通話がオフか、ヘッドセットの有無、端末の置き方 |
| 手伝い役 | 起動のしかた（[diagnostics.md](diagnostics.md) のどの方法か）、pid と uid |
| 環境の報告 | 通話の前と通話中の2つ（コピーした文をそのまま） |
| 試験ごと | 画面の記録（試験の番号と方式、始めた・止めた時刻、出力先 `getRoutedDevice()` の種類、音声のモード、マイクのミュート、作れなかったときの例外の文、止まった理由）。協力者の答え（1回目・2回目が聞こえたか、大きさ） |
| 試験3 | 画面の記録の `isPstnCallAudioInterceptable` と、何回目か。通話が切れたか（電話の画面を目で見る） |
| 受話の音量 | 同時に使ったときだけ：開始の報告の `isClientSilenced()` |

## 6. 結果の判断

| 結果 | 判断 |
| --- | --- |
| 試験1 で、2回とも聞き取れる | 合格。マイクを止めても注入が届く（[decisions.md](../../docs/decisions.md) の未解決 1 の、この端末での答え）。ADR-028 へ |
| 試験1 では届かず、試験3 で2回とも聞き取れる | 試験1 と同じ条件（マイクを止めた状態）で届いたので、合格の条件を満たす。redirection の方式で届いたことを記録し、ADR-028 で扱う（いまの設定では選べない） |
| 試験1・3 で届かず、試験2 で届く | 試験0 と大きさを比べる。試験2 のほうが明らかに大きく、出力先が `TYPE_TELEPHONY` なら**条件つき合格**：マイクのミュートは使えない。A4・A5 は、設定の「困ったとき」の「端末のマイクを止めない」をオンにして、マイクを止めずに静かな部屋で行い、未解決 1 の、この端末での答えを「止められない」と書く。差がなければ、回り込みと考えて不合格 |
| どれも届かない | 記録に直せる原因（出力先、例外の文）が見えたら、直してもう1回（2回まで）。見えなければ、注入はあきらめて、練習だけで使う |
| 試験4 で、2回とも聞き取れる | スピーカーで流す形の候補。通話のエコー除去で消される見込みが高いので、届かなくても記録して次へ進む（スピーカーの形は設定から外したので、いまの設定では選べない） |

## 7. うまくいかないとき

| 症状（記録の行） | 見当 | すること |
| --- | --- | --- |
| 「通話中ではない」で止まる | 通話の前に開始した。音声のモードが `MODE_IN_CALL` でない | 通話がつながってから開始する。環境の報告で音声のモードを見る |
| 「TELEPHONY(18) の出力が見つからない」 | この端末・この通話で、通話用の出力が出ていない | 記録する。試験1・2 は飛ばす |
| 「出力先の指定 setPreferredDevice … → false」 | 出力先の指定を断られた | 記録する |
| 出力先 `getRoutedDevice()` の行に「指定と違う」 | 指定した出力先に向かなかった | 記録する。相手に届いたかと合わせて判断する |
| 「作れなかった: SecurityException …」 | 手伝い役の権限が足りない | 環境の報告の権限の行（`MODIFY_PHONE_STATE`、`CALL_AUDIO_INTERCEPTION`）を記録する |
| 試験3 で「UnsupportedOperationException:  PSTN Call audio not accessible」 | `isPstnCallAudioInterceptable` が false | 記録する。試験3 はそれ以上しない |
| 「音声のモードが … になった」で止まる | 通話が切れた | 電話の画面を確かめて記録する |
| 「書き込みの失敗」で止まる | 通話が終わって、システムが音を止めた（試験3 で起きやすい） | 通話が続いているか確かめ、記録する |
| 「手伝い役の uid が 2000（shell）ではない」 | 手伝い役が shell で動いていない | [diagnostics.md](diagnostics.md) の起動のしかたで起動し直す |
| 試験0・4 で、何も聞こえない | 音が小さい | 音量を -6 にして、もう1回 |
| ボタンが押せない | 手伝い役が止まっている | [diagnostics.md](diagnostics.md) の起動のしかたで起動し直す |

## 8. 画面の部品（5. 送話の試験）

| 部品 | はたらき |
| --- | --- |
| 試験 | 試験0〜4 を選ぶ。選んだ試験の「始める前にすること」が出る |
| 遅らせる | 0・5・10・30 秒。「開始」を押してから鳴らし始めるまでの秒数（端末から離れてから鳴らしたいとき） |
| 鳴らす | 10・20・30 秒。この秒数で自動で止まる。既定は 20 秒（目印の音は2回） |
| 音量 | -24・-18・-12・-6 dBFS（ピーク）。既定は -12 |
| 開始 | 試験を始める。試験1〜3 は、通話中（`MODE_IN_CALL`）でないと始まらない。試験1〜3 は、鳴らしている間に通話が終わる（音声のモードが `MODE_IN_CALL` でなくなる）と、自動で止まる |
| 止める | すぐ止める（遅らせて待っている間も） |
| 記録 | いまの試験の記録。電話番号と名前は入らない |
| 記録をコピー | この画面で行った試験の記録を、まとめてコピーする |
