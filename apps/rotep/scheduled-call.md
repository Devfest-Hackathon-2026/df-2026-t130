# 時間を指定した電話を確かめる

指定した時刻に、本人がスマホを見ていなくても AI が電話を最後まで済ませる機能（[ADR-040](../../docs/decisions.md)）を、Nothing Phone (2a) で確かめる手順です。本人が行います。発信は「全自動で電話をかける」だけなので、[a4.md](a4.md) が通っていることが前提です。**コードの試験では、実際の発信は確かめられません。**

## 前に要るもの

- [a4.md](a4.md) が通っていること（`MANAGE_ONGOING_CALLS` の AppOps を許可済み）。通っていなければ、この機能は使えません（確認の画面に理由が出ます）
- 手伝い役が動いていること（[diagnostics.md](diagnostics.md)）。端末を再起動すると消えます（PC なしの形でペアリングしてあれば、Wi-Fi につながったところでアプリが起動し直します。再起動のあとも動くことは、スマホで確かめました。2026-11-10）。「開発者向けオプションを普段は切っておく」がオンのときは、電話の時刻にアプリが起動します（[diagnostics.md](diagnostics.md) の 11 節。スマホでは、まだ確かめていません）
- 設定：「電話のしかた」は「全自動で電話をかける」
- 相手役は、説明して同意をもらった協力者。**お店、会社、時報、緊急の番号にはかけない**
- 通知を許可しておく（許可がないときと、このアプリの通知を端末の設定で切っているときは、予約できません）

## 1. 予約する

1. 依頼を作り、確認の画面まで進める（協力者の番号は「手で入力する」から入れる）
2. 確認の画面を下へ進める。「時間を指定して電話する」の中の「日時を選ぶ」を押す
3. 日付を選び、時刻を 3 分以上先にして（2 分より近い時刻と、21 時から 8 時までは選べません）、「11月10日(火) 11:00に電話する」の形のボタンを押す
4. 最初の画面に戻り、上の帯に「11月10日(火) 11:00に △△ へ電話します」の形の文と「取り消す」が出る。状態バーにアラームの印が出て、ロック画面の次のアラームにもこの時刻が出る（時刻どおりに起こすための、Android の仕組みです）

## 2. 試す

| 番号 | すること | 期待すること |
| --- | --- | --- |
| 1 | 帯の「取り消す」を押す | 帯が消える。アラームの印が消える。時刻になっても何も起きない。次の試験のために、予約をやり直す |
| 2 | 予約して、1 分前の通知を待つ | 「まもなく AI が電話をかけます」が出る。通知の「取り消す」を押すと通知と帯が消え、電話はかからない（取り消せなかったときは、通知「取り消せませんでした」が出る）。もう一度予約して次へ |
| 3 | 予約して、画面を消してロックし、端末に触らない | 1 分前の通知が出て、時刻ちょうどに電話がかかる（数秒の遅れはある）。協力者が出ると AI が話し始める。終わると電話が切れる |
| 4 | 3 のあと | 通知「電話が終わりました」に結果が出る。アプリを開くと結果の画面が出る。「最初に戻る」のあと、最初の画面の「電話の記録」にも出る（記録がオフのときは「前回の電話」） |
| 5 | 予約のあと、アプリを最近使ったアプリから消して（強制停止はしない）、ロックして待つ | 3 と同じ。プロセスが終わっていても動くことの確かめ |
| 6（できれば） | 予約のあと、PC で `adb shell dumpsys deviceidle force-idle`（時刻の 2 分以上前に）。ロックして待つ。あとで `adb shell dumpsys deviceidle unforce` | Doze でも時刻どおりにかかる |
| 7 | 通話の途中で協力者が長く話す（通話の上限まで）。試すなら、依頼の「通話の上限（分）」を 1 にする | 上限で AI が「その点は確認して、改めてこちらから折り返しご連絡いたします。」と伝え、電話が切れる。アラームの音や振動はない。結果の通知が出る |
| 8 | 通話の途中で Wi-Fi とモバイルデータを切る（AI が切れる） | AI が切れて、**文を伝えずに電話が切れる**（話す者がいないため）。結果の通知が出る |
| 9 | 通話の途中でアプリの通話中の画面を開き、「AI を止めて本人に代わる」を押す | AI が止まり、電話は切れない。本人が話せる |
| 10 | 予約のあと、手伝い役を止めて（診断の「終了」）時刻を待つ（「開発者向けオプションを普段は切っておく」はオフのまま） | 電話はかからない。通知「電話をかけませんでした」に、手伝い役のことが書いてある |
| 11 | 予約のあと、設定の「電話のしかた」を「電話をかける」に変えて時刻を待つ | 電話はかからない。通知に「設定が変わって」と出る |
| 12 | 予約のあと、自分の別の電話をかけた状態で時刻を待つ | 電話はかからない。通知に理由が出る |
| 13 | 予約のあと、時刻の前に端末を再起動する（アプリは開かない） | 手伝い役を起動し直さなくても、通知「電話をかけませんでした」に「11月10日(火) 11:00の △△ への電話は、かけられませんでした（端末の再起動などで予定が消えました）…」の形の文が出る（通知を見逃しても、アプリを開くと同じ文が出る）。電話はかかっていない |
| 14 | 「電話をかける」で確認の画面を開く | 「時間を指定して電話する」の「日時を選ぶ」が押せず、「全自動で電話をかける」にするよう書いてある |
| 15 | ほかの AI から依頼を送り（[mcp/README.md](mcp/README.md)）、「内容を見る」で確認の画面を開く | 「時間を指定して電話する」が使える。時刻は本人が選び、この画面で承認したときだけ予約になる。`call_at` の付いた依頼では「ほかの AI の希望：11月10日(火) 11:00」の形で出て、選べる時刻なら「日時を選ぶ」の最初の時刻になる |
| 16 | 「電話をかける」と「承認して電話する」の普通の流れを 1 回通す | 今までどおり。本人に代わる動きも変わらない |

## 3. うまくいかないときの切り分け

通話のあとすぐ、PC で（番号が出ることがあるので、手元にだけ置く）：

```bash
adb logcat -d -s Rotep/schedule
```

```bash
adb shell "dumpsys alarm | grep -A3 io.github.incallagent.rotep"
```

| 見えたこと | 意味 | すること |
| --- | --- | --- |
| `dumpsys alarm` に出ない（時刻の前） | アラームがない | 帯は出ているか。強制停止や再起動をしていないか |
| `Rotep/schedule` に `due` が出ない | 時刻に起きなかった | バッテリーの設定で「制限」になっていないか見る。Nothing の省電力の設定も見る |
| `not placed: check` | 検査で止まった | 通知の理由のとおりに直す |
| `foreground service` の例外が出る | サービスを起動できなかった | 記録して知らせる（この端末の制限かもしれません） |
| `placing the call` のあと、通話中に音が聞こえない | 手伝い役の受話が画面オフで止められた可能性 | 画面をつけたままでも同じか比べる。記録して知らせる |

## 4. 後片付け

- 試したあとの予約が残っていないことを確かめる（帯が出ていない）
- AppOps や通話の音など、残りの片付けは [a4.md](a4.md) の 5 節のとおり

記録すること（番号と名前は書かない）：1〜16 の結果。時刻からの遅れ（秒）。発信の時に画面がどうなったか（標準の電話アプリの画面が出たか）。

## 5. 調べて確かめたこと

GrapheneOS 17（AOSP 相当）のソース（frameworks-base `138e1794`、Telecomm `21585d3`）と、Android の公式文書で確かめたことです。**Nothing Phone (2a) の Android 16 で同じかは、この手順で確かめます。**

| 確かめたこと | 分かったこと | 出典 | 確度 |
| --- | --- | --- | --- |
| `setAlarmClock` の権限 | exact アラームには `USE_EXACT_ALARM` か `SCHEDULE_EXACT_ALARM` が要る。`USE_EXACT_ALARM` は Android 13 から、インストールで付く | `AlarmManagerService.java` 2868〜2925 行、公式の Alarms の文書 | 事実 |
| Doze | alarm clock は `FLAG_WAKE_FROM_IDLE` が付き、Doze で遅らされず、Doze の予定を前倒しする。App Standby の対象外 | `AlarmManagerService.java` 2845、2528、2658〜2671、4462 行 | 事実 |
| バックグラウンドからのサービス起動 | alarm clock の配信には、フォアグラウンドサービスの起動を許す一時の許可（`REASON_ALARM_MANAGER_ALARM_CLOCK`）が付く。長さの既定は 10 秒。バックグラウンドを制限されたアプリでも通る | `AlarmManagerService.java` 930〜936、2896、757 行、`ActiveServices.java` 1089〜1090、2250〜2258、2401〜2402 行 | 事実。10 秒の中で起動するよう、受信の最初に起動する |
| phoneCall 型のサービス | `FOREGROUND_SERVICE_PHONE_CALL` と、`MANAGE_OWN_CALLS` か標準の電話アプリの役割が要る。マイクなどの「使用中」の権限の制限は対象外 | `ForegroundServiceTypePolicy.java` 345〜357 行、公式の restrictions-bg-start | 事実 |
| Doze 中のネットワークとウェイクロック | フォアグラウンドサービスの状態のアプリは、Doze のネットワークの制限と部分ウェイクロックの無効化の対象外 | `NetworkPolicyManager.java` 192、841 行、`PowerManagerService.java` 4835〜4845 行 | 事実 |
| ロック中の Keystore | 鍵は既定で「解錠中だけ」ではない（`unlockedDeviceRequired` の既定は false）。`KeystoreCipher` は設定していないので、ロック中も使える。読めないときは 1 秒おきに 5 回まで読み直す | `KeyGenParameterSpec.java` 1042 行 | 事実（端末は未確認） |
| 発信と前面 | `TelecomManager.placeCall` の側に、アプリが前面にいることや画面の解錠を確かめる処理はない | `TelecomServiceImpl.java` placeCall | 事実（端末は未確認） |
| アプリのプロセスが終わっていたとき | 手伝い役はアプリとのつながりが切れると、2〜5 秒おきに登録を試し、その登録がアプリのプロセスを起こす。発信の時刻に手伝い役を 15 秒まで待つ | `shell/HelperMain.kt`、`shell/HelperProtocol.kt` の `HelperLifetime`、`shell/HelperService.kt` | 事実（コード） |
