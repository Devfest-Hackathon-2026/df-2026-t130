# A6：電話の操作を AITEL の画面で行う（相手が出たことの検知を含む）

本人が Nothing Phone (2a) で行う手順です。発信のあと、標準の電話アプリの画面に切り替えなくても、AITEL の通話の画面で操作できるかを確かめます。

- 相手は、目的を説明して同意をもらった協力者だけです。お店、会社、時報、緊急の番号にはかけません
- 通話の画面の「スピーカー」と「キーパッド」は「全自動で電話をかける」だけで使えます。Telecom の中にしか、この 2 つを操作する口がないためです。「電話をかける」では「電話の画面」のボタンから電話アプリの画面を開きます
- 「相手が出た」と「切った」は、アプリが読み取れないときの予備としてだけ出ます

## 1. 入れ替える

```bash
adb install -r apps/rotep/build/outputs/apk/debug/rotep-debug.apk
```

入れ直すと、古い手伝い役は自分で終わります。手伝い役を起動し直します。PC なしでペアリングしてあって、自動の起動がオンなら、アプリが起動します（スマホでは、まだ確かめていません）。起動しないときは、通知の「起動」か、診断の画面（設定の「困ったとき」の「診断の画面を開く」から開きます）の「手伝い役を起動」で起動します（[diagnostics.md](diagnostics.md) の 9 節。診断の画面からの起動は、スマホで通りました。通知の「起動」は、まだ確かめていません）。PC からは、同じ文書の 4-2 のとおり、次のコマンドです。

```bash
adb shell sh /data/local/tmp/rotep-helper.sh
```

## 2. 通話の前に、読み取りを確かめる

```bash
adb shell "dumpsys telephony.registry | grep -E 'Phone Id|mRingingCallState|mForegroundCallState|mBackgroundCallState'"
```

どの `Phone Id` も、3 つの値が `0` か `-1` であること（通話がない）。出ないときは、この端末では読み取りが使えません。「相手が出た」の予備が出る形で続けて、結果を記録してください。

## 3. 「電話をかける」で試す

設定の「電話のしかた」を「電話をかける」にします。依頼を作り、確認の画面で「承認して電話する」を押します。

| 番号 | 確かめること | 見るところ | 期待すること |
| --- | --- | --- | --- |
| 1 | AITEL の画面に戻る | 画面 | 電話の画面が一瞬出たあと、数秒以内に AITEL の通話の画面に戻る |
| 2 | 呼び出し中は AI が話さない | 画面と協力者 | 「呼び出し 0:xx」が進むだけで、AI の声はしない。「相手が出た」のボタンは出ない（20 秒たっても出ないときの予備としてだけ、そのあと出る） |
| 3 | 相手が出たら、何も押さなくても AI が話し始める | 画面と協力者 | 協力者が出ると「AI が会話しています」になり、AI が名乗る |
| 4 | マイクのボタン | 画面と協力者 | 設定どおり「マイクを戻す」と出て、マイクが止まっている（押すと「マイクを止める」に変わり、協力者に本人の声が聞こえる） |
| 5 | 本人に代わる | 画面と協力者 | 「AI を止めて本人に代わる」で AI が止まり、本人が話せる。マイクのボタンも使える |
| 6 | 電話を切る | 画面 | 「電話を切る」で通話が終わり、結果の画面になる |
| 7 | 相手が先に切る | 画面 | もう 1 回かけて、協力者に切ってもらう。「切った」を押さなくても結果の画面になる |
| 8 | 電話の画面を開く | 画面 | 「電話の画面」のボタンで電話アプリの通話の画面が出る。キーパッドとスピーカーはそこで使える。最近使ったアプリから AITEL に戻れる |
| 9（できれば） | 保留 | 画面 | もう 1 回かけて、AI が話している途中で電話の画面の「保留」を押す。数秒で AI が止まり、本人に代わる（「保留になったか、ほかの通話が始まりました」） |
| 10（できれば） | ほかの通話の途中 | 画面 | 別の電話をかけた状態で「承認して電話する」を押す。「ほかの通話の途中なので、電話をかけません」と出て、発信しない |

AI の用件が終わったとき（AI が end_call を呼んだとき）は、「電話をかける」でも手伝い役が電話を切ります。切れないときは、電話の画面で切るよう案内します。

### 検知の確かめ方

呼び出し中と、相手が出たあとに、PC で読み取ります。

```bash
adb shell "dumpsys telephony.registry | grep -E 'mForegroundCallState'"
```

呼び出し中は `3` か `4`、相手が出たあとは `1` であること。通話のあと、ログで順番を確かめます（番号が出たら書き写さない）。

```bash
adb logcat -d -s Rotep/control Rotep/call
```

`manual: call placed` のあと、`manual: answer seen` と `phase RINGING -> TALKING` がこの順に出ること。`manual: stopped watching` や `manual: not watching` が出たときは、手伝い役が読み取れなかった（予備のボタンが出る）ことを意味します。Telecom の記録と比べるときは、次の `SET_ACTIVE` の時刻と、`answer seen` の時刻の差が 2 秒以内であることを見ます（dumpsys には番号が出ることがあるので、手元にだけ置く）。

```bash
adb shell "dumpsys telecom | grep -E 'SET_DIALING|SET_ACTIVE'"
```

## 4. 「全自動で電話をかける」で試す

「全自動で電話をかける」は [a4.md](a4.md) の許可が要ります。一度だけ許可します。診断の画面の「全自動を許可」を押すか（スマホでは、まだ確かめていません）、USB デバッグがオンの間に、PC から次を実行します。

```bash
adb shell appops set io.github.incallagent.rotep MANAGE_ONGOING_CALLS allow
```

設定の「電話のしかた」を「全自動で電話をかける」にして、3 と同じように電話をかけます。a4.md の表に加えて、次を見ます。

| 番号 | 確かめること | 見るところ | 期待すること |
| --- | --- | --- | --- |
| 1 | 全部のボタン | 画面 | 相手が出ると「スピーカー」「マイクを止める」「キーパッド」「電話を切る」が並ぶ。電話アプリの画面でも同じ状態になる |
| 2 | スピーカー | 画面と音 | 押すと「スピーカー オン」になり、本人に代わったあとスピーカーから相手の声が聞こえる（AI が話す間に消音なら、一言の案内が出る）。AI の声が相手に届き続けること（経路の変更が AI の声を止めないかは未確認。ここで確かめる） |
| 3 | キーパッド | 画面と協力者の答え | 押した番号が画面に出て、協力者に「ピッ」と聞こえる |
| 4 | マイクの設定 | 画面 | 「端末のマイクを止めない」がオンのときは、AI が話す間マイクとスピーカーのボタンが押せず、理由の一言が出る |

許可があっても、設定が「電話をかける」のままなら、その形で動きます。

## 5. 元に戻す

- [a4.md](a4.md) の 5 節のとおり、AppOps を `default` に戻し、サービスが無効に戻っていること、アプリがつながったままでないことを確かめる
- 通話のあと、普通の発信を 1 回して、スピーカーやミュート（電話の画面）が入っていないことを確かめる（Telecom が元に戻します）

## 6. うまくいかないとき

| 起きたこと | すること |
| --- | --- |
| AITEL の画面に戻らない | 手伝い役が動いているかを診断の画面で見る。電話の画面の通知や、最近使ったアプリから戻れる（今までと同じ） |
| 相手が出ても AI が話し始めない | 20 秒たつと「相手が出た」が出るので押す。2 節の読み取りの結果と、`manual: ...` のログを記録する |
| 「電話を切る」で切れない | 電話の画面で切って「切った」を押す（画面に案内が出る）。ログの `manual: hang up` を記録する |
| マイクのボタンが効かない | 電話の画面でマイクを止める（画面に案内が出る） |

記録には、番号と名前を書きません。試した結果（3 節の 1〜10、4 節の 1〜4）、発信から AITEL に戻るまでの秒数、検知の時刻の差を書きます。
