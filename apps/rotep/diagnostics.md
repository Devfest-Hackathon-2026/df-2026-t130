# 診断の画面で、手伝い役を確かめる手順

診断の画面と PC の adb で、手伝い役が動くかを確かめる手順です。診断の画面は、アプリの設定の「困ったとき」にある「診断の画面を開く」で開きます（ホーム画面のアイコンはありません）。

- 所要時間：30〜40分（協力者に電話する時間は、そのうち10分ほど）
- **Shizuku は使いません**（この端末の Android 16 では、Shizuku の手伝い役が起動できなかったため）。手伝い役は、PC の adb から、shell の権限で直接起動します（scrcpy と同じ形：`app_process`）。起動に使うスクリプトは [helper/rotep-helper.sh](helper/rotep-helper.sh) です
- PC なしで起動するときは [9 節](#9-pc-なしの起動ワイヤレスデバッグ) を見てください（ADR-041）。ここから下の 8 節までは、PC を使う形の手順です。普段は開発者向けオプションを切っておく形は [11 節](#11-開発者向けオプションを普段は切っておくadr-049) です

## 1. 何を確かめるか（合格の条件）

| 番号 | 条件 | 見るところ |
| --- | --- | --- |
| 1 | 手伝い役が、PC の adb から起動して、ちゃんと終わる | 手順 5〜7 と、手順 15・17 |
| 2 | 環境の報告が、通話の前と通話中に取れる | 手順 9 と手順 11 |
| 3 | 協力者が話したとき、受話の音量の棒が動く | 手順 13 |
| 4 | 録音の名義に誤りがない | 画面の上に赤い帯が出ない。報告の「録音の名義」の行が「正しい（shell）」 |

4つとも満たしたら合格です。1つでも違ったら、原因を直してやり直します。

## 2. 用意するもの

- PC（`adb` が使える。USB ケーブルでつなぐ）。コマンドは、**リポジトリの一番上のフォルダ**で、PowerShell で実行します。Git Bash では、`/data/...` が Windows のパスに変えられてしまうので、各コマンドの前に `MSYS_NO_PATHCONV=1` を付けます
- Nothing Phone (2a)（USB デバッグはオン）
- 協力者1人（予備1人）。事前に説明して同意をもらっていること：AI の実験であること、相手の声の音量を調べること、**音は保存しないこと**
- 協力者の電話の番号。**この資料にも、記録にも、書かない**

## 3. 守ること

- 電話をかける相手は、同意した協力者だけです。お店や会社には、かけません。緊急の番号では試しません
- 通話の音声は、保存しません。画面に出るのは、音量の数字と棒だけです
- 環境の報告には、電話番号も名前も入りません。コピーして記録に貼ってかまいません
- 検証の間、Wi-Fi 通話はオフ。VoLTE で通話します

## 4. 手順

### 4-1. アプリを入れる

1. 端末を USB でつなぎ、端末に出る「USB デバッグを許可しますか」を許可します
2. つながったか確かめます

   ```bash
   adb devices
   ```

   端末の行に `device` と出れば OK です（`unauthorized` なら、端末の許可の画面を確かめます）

3. APK を入れます。APK は `apps/rotep/build/outputs/apk/debug/rotep-debug.apk` です（`./gradlew :apps:rotep:assembleDebug` で作ります）

   ```bash
   adb install -r apps/rotep/build/outputs/apk/debug/rotep-debug.apk
   ```

   - `Success` と出れば OK です
   - 署名が合わないと言われたら、一度消してから入れ直します（アプリのデータは消えます）

     ```bash
     adb uninstall io.github.incallagent.rotep
     ```

4. アプリを開き、設定の「困ったとき」から **「診断の画面を開く」** を押します

### 4-2. 手伝い役を PC から起動する

5. 診断の画面を開きます。「1. 手伝い役の起動」の欄に、次の2本のコマンドが出ています。「2. 手伝い役の状態」は「つながっていない」です
6. スクリプトを端末に置きます（**最初の1回だけ**。スクリプトを変えたときも）

   ```bash
   adb push apps/rotep/helper/rotep-helper.sh /data/local/tmp/rotep-helper.sh
   ```

   `1 file pushed` と出れば OK です
7. 手伝い役を起動します

   ```bash
   adb shell sh /data/local/tmp/rotep-helper.sh
   ```

   - `rotep-helper: started` と出れば、起動は頼めています。数秒で、画面の状態が「動いている」になり、`pid=… uid=2000 version=…` と出ます
   - **pid をメモします**（手順 15 で使います）
   - このコマンドは、アプリを入れ直しても同じです。手伝い役は、USB を抜いても動き続けます
   - 状態が「動いている」にならないときは、「6. うまくいかないとき」を見ます

手伝い役の寿命：

- アプリが落ちても、手伝い役は**残ります**。つなぎ直しは、**すぐ**（1秒以内）に1回します。つながらなければ **2秒後**、そのあとは **5秒おき**にやり直します（つなぎ直すときに、アプリのプロセスも立ち上がります）
- 診断の画面を閉じても、終わりません
- 終わるのは、次の4つのときだけです：
  1. 「終了」を押したとき
  2. アプリが入れ直されたとき（下の表のとおり、自分で終わります）
  3. アプリにつながらないまま10分たったとき
  4. 端末の再起動
- 二重に起動すると、新しいほうが残り、古いほうは終わります

アプリを入れ直したとき（手伝い役は、起動したときのアプリの版と uid を覚えていて、つなぎ直しに行くたびに確かめます）：

| 入れ直し方 | アプリの uid | 古い手伝い役 |
| --- | --- | --- |
| `adb install -r …` | 変わらない | つなぎ直しに来たところで、アプリが「版が合わない」と断る。手伝い役は**自分で終わる** |
| `adb uninstall` のあとに入れ直す | **変わることがある**（変わらないこともある） | uid が変わったとき：Provider の持ち主の uid が違うので、手伝い役は**自分で終わる**。つなぎ直しは続けない（5秒おきにアプリを起こし続けることはない）。変わらなかったとき：`install -r` と同じく、版で断られて終わる |

- 消してから入れ直すまでの間は、アプリが無いので、手伝い役は（2秒後、そのあとは5秒おきに）Provider を探すだけです。アプリは起動しません。10分以内に入れ直されなければ、10分で終わります
- どちらの場合も、入れ直したあとは、手順 7 で手伝い役を起動し直します

### 4-3. 通話の前の環境の報告

8. 「3. 環境の報告」の「報告を取る」を押します
9. 次を見ます。「コピー」を押して、記録に貼ります

   | 行 | 期待 |
   | --- | --- |
   | 手伝い役 | `uid=2000 (shell)` |
   | 権限 | `CAPTURE_AUDIO_OUTPUT` と `MODIFY_PHONE_STATE` が「あり」 |
   | 音声のモード | `MODE_NORMAL (0)`（通話前） |
   | 録音の名義 | `package=com.android.shell uid=2000 → 正しい（shell）` |

### 4-4. 協力者に電話する

10. 協力者に、普通の電話のアプリで電話します（VoLTE。Wi-Fi 通話はオフ）。相手が出たら、次をします
    - スピーカーにしない。Bluetooth やヘッドセットは外す
    - **電話の画面で、マイクをミュートにする**（受話の確認に影響しません。自分のマイクの音を、相手の声と取り違えないための対照です）
11. 診断の画面に戻ります（アプリの設定の「困ったとき」から開くか、最近使ったアプリから選ぶ）。「報告を取る」を押して、コピーし、記録に貼ります

    | 行 | 期待（通話中） |
    | --- | --- |
    | 音声のモード | `MODE_IN_CALL (2)` |
    | マイクのミュート | はい |
    | 出力の装置 | `TELEPHONY(18)` があるか **記録する**（あるか、ないかが分かればよい） |
    | `isPstnCallAudioInterceptable` | 値を記録する |

### 4-5. 受話の音量

12. 「4. 受話の音量」の「開始」を押します。1秒ほどで「開始の報告」が出ます。次を見ます

    | 行 | 期待 |
    | --- | --- |
    | `getAudioSource()` | `VOICE_DOWNLINK(3)` |
    | `getSampleRate()` | 使ったレート（多くは 48000 Hz）。記録する |
    | `getRoutedDevice()` | 種類を記録する |
    | `isClientSilenced()` | `false` |
    | 録音の名義 | 「正しい（shell）」 |

13. 協力者に話してもらいます（例：「テスト、さくら、いち、に、さん」）。**話している間、棒が動けば合格**です
    - 話していない間は、「いまは無音」と出て、棒は止まります
    - 「受け取ったサンプル」の数が増え続けているか見ます。増えているのに棒が動かないときは、音が無音で来ています
14. 「停止」を押します（押さなくても、60秒で自動で止まります）。「停止の報告」が出るので、「音量の報告をコピー」を押して、記録に貼ります

    **余裕があれば**：「開始」から「停止」の間に、PC で次を実行して、録音の行を記録します（録音の元が `3`＝`VOICE_DOWNLINK`）。結果は手元にだけ置きます

    ```bash
    adb shell dumpsys audio
    ```

### 4-6. 終わらせる

15. 手伝い役を終わらせて、残っていないか確かめます
    1. 診断の画面の「2. 手伝い役の状態」で「終了」を押します。状態が「終了中…」から「つながっていない」になります（数秒）
    2. PC で、手伝い役が残っていないか調べます

       ```bash
       adb shell pidof rotep-helper
       ```

       **何も出なければ**、手伝い役は残っていません。数字が出たら、残っています。手順 7 でメモした pid と同じか見ます
    3. `pidof` がない端末では、次で調べます。`rotep-helper` の行が出たら、残っています

       ```bash
       adb shell "ps -A | grep rotep-helper"
       ```

16. 電話の画面で、**マイクのミュートを戻します**。通話を切ります
17. 診断の画面を「戻る」で閉じます（閉じても、手伝い役は終わりません。終わらせるのは「終了」だけです）。そのあと、もう一度 15-2 を実行して、手伝い役がいないことを確かめます

### 4-7. 任意：つなぎ直しと、入れ直しの確認

合格の条件には入りません。手伝い役の寿命の動きを確かめます。手順 7 で手伝い役を起動し、「動いている」にしてから行います。終わったら、手順 15 で終わらせます。

**アプリが落ちても、手伝い役が残るか。**

```bash
adb shell am force-stop io.github.incallagent.rotep
```

- 続けて `adb shell pidof rotep-helper` を実行します。数字が出れば、手伝い役は残っています
- 数秒待ってから、診断の画面を開きます（設定の「困ったとき」）。状態が「動いている」に戻っていれば、手伝い役がつなぎ直しました（`pid` は前と同じ）

**アプリを入れ直したら、古い手伝い役が自分で終わるか。** 入れ直し方は2つあります（動きの違いは、4-2 の表のとおりです）。

`adb install -r`（uid は変わらない）：

- 手順 3 の `adb install -r …` をもう一度実行します
- 数秒待って、`adb shell pidof rotep-helper` を実行します。**何も出なければ**、古い手伝い役は、アプリに断られて終わりました（ログに `register refused for good: 版が合わない`）

消してから入れ直す（uid が変わることがある）。アプリのデータが消えるので、消えてよいときだけ行います：

- `adb uninstall io.github.incallagent.rotep` を実行して、続けて手順 3 の `adb install -r …` で入れ直します。消している間は、ログに `handoff: provider not found` が出ます（手伝い役は探し続けます）
- 数秒待って、`adb shell pidof rotep-helper` を実行します。**何も出なければ**、古い手伝い役は自分で終わりました。ログは、次のどちらかです
  - uid が変わったとき：`handoff: the provider does not belong to the app (provider uid=…, app uid=…)`、続けて `exit: アプリが入れ直されたらしい（…）`
  - uid が変わらなかったとき：`register refused for good: 版が合わない`（`install -r` と同じ）
- 手伝い役がアプリを見つけた最初の1回で、アプリのプロセスが立ち上がります。その1回で終わり、5秒おきには続きません

どちらのあとも、手順 7 の起動のコマンドを、もう一度実行します（手順 6 のスクリプトは、置き直さなくてかまいません）。

## 5. 記録すること

手元の記録にだけ置きます（リポジトリには書きません）。電話番号と名前は書きません。

| 項目 | 内容 |
| --- | --- |
| 条件 | 日時、Android の版、ビルド番号（報告に出る）、VoLTE で通話したか、Wi-Fi 通話がオフか、スピーカー・ヘッドセットの有無、マイクをミュートしたか |
| 手伝い役の起動 | 手順 7 で起動できたか、「動いている」になるまでの時間、`pid` と `uid` と `version`、ログの `context: built via …` の行（6-3）、終了のあとに残っていないか（手順 15、17） |
| 4-7 の確認（任意） | アプリを止めたあとも残ったか、つなぎ直したか。入れ直したあと（`install -r` と、消してから入れ直した場合）、古い手伝い役が終わったか。終わったときのログの行 |
| USB を抜いたあと（任意） | 「動いている」のあとで USB を抜き、画面を消して5分おいたあとも、「報告を取る」が通るか |
| 環境の報告 | 通話の前と通話中の2つ（コピーした文をそのまま） |
| 受話の音量 | 使ったレート、`getAudioSource()`、`getRoutedDevice()` の種類、`isClientSilenced()`、棒が動いたか、話しているときと黙っているときのおおよその dBFS、開始の報告と停止の報告 |
| 失敗したとき | 画面の「出来事」の欄、`adb logcat` の出力（6-3 の方法） |

## 6. うまくいかないとき

### 6-1. 画面の表示で分かるもの

| 症状 | 見当 | すること |
| --- | --- | --- |
| 手順 7 のあと、「つながっていない」のまま | 手伝い役が起動できなかった、または、アプリにつなげない | 6-3 でログを取る。起動そのものを調べるには、6-4 を見る |
| 出来事に「版が合わない手伝い役を断った」 | 起動した手伝い役の版と、入っているアプリの版が違う（入れ直しの前の手伝い役） | 手伝い役は自分で終わる。手順 7 をやり直す |
| 出来事に「手伝い役が、つながる前にいなくなっていた。登録を断った」 | 手伝い役が、アプリに登録を頼んだすぐあとに終わった（`kill` した、など）。アプリは「動いている」にしていない | 手順 7 をやり直す |
| 出来事に「新しい手伝い役に替えた」 | 手伝い役を2つ起動した | 新しいほうが残り、古いほうは終わる。そのままでよい |
| 画面の上に赤い帯（録音の名義が shell になっていない） | 手伝い役が shell（uid 2000）で動いていない、または、名義を合わせられなかった | 報告の「手伝い役」の行が `uid=2000 (shell)` か見る。6-3 の `context:` の行を記録する |
| 黄色の帯（システムが録音を黙らせている） | `isClientSilenced = true` | 報告をそのまま記録する。この状態で棒が動かなければ不合格 |
| 開始しても、すぐ止まる | 録音を作れなかった | 「止まった理由」と「試したレート」の行を記録する |
| 「自分の録音が見つからない」 | 録音がシステムの一覧に出ていない | 通話中か確かめて、もう一度開始する。記録する |
| 「受話のデータが○秒以上来ていない」 | 通話の音が来ていない | 通話中か、通話の前に開始していないか確かめる |
| サンプルは増えるが、棒がずっと動かない | 無音で来ている。相手が話していない、または黙らされている | 協力者に大きめの声で話してもらう。報告の `isClientSilenced` を見る |
| 手伝い役が残った | 終了の処理が働かなかった | `adb shell pidof rotep-helper` の pid を `adb shell kill <pid>` で止める。残ったことを記録する |

### 6-2. 再起動したとき

端末を再起動すると、手伝い役は消えます。手順 7 から、やり直します（スクリプトは端末に残っています）。

### 6-3. ログを取る

PC で、次を実行してから、手順 7 や画面の操作をします。止めるときは Ctrl+C です。

```bash
adb logcat -s RotepDiag:V RotepHelper:V
```

うまくいくと、次の順に出ます（`pid` などの数字は違います）。

| タグ | 行 | 意味 |
| --- | --- | --- |
| `RotepHelper` | `helper main: uid=2000 pid=…` | 手伝い役が shell で動き始めた |
| `RotepHelper` | `context: built via systemMain (sm appInfo appContext shell=true)` | Context を作れた。`!` が付いた語（例 `!appInfo`、`!sm`）は、その手順が使えず飛ばした印。`shell=false` は名義を作れなかった。`via new-thread` なら、予備の道を使った |
| `RotepHelper` | `started: uid=2000 pid=… version=…` | 手伝い役の本体ができた |
| `RotepHelper` | `registered with the app` | アプリが受け取った |
| `RotepDiag` | `手伝い役がつながった（pid=… uid=2000）` | アプリの側でも「動いている」になった |

途中で止まっているとき：

| 最後に出た行 | 見当 |
| --- | --- |
| 何も出ない | 手伝い役のプロセスが起動していない。6-4 を見る |
| `helper main: this process is not the shell user` | shell 以外で起動した。`adb shell` から直接実行する |
| `context: systemMain threw: …` | `systemMain()` が例外を出した。続けて `context: built via systemMain (… !sm …)` と出れば、例外は無視して進んだ。この行を記録する |
| `helper main: no Context could be built, exiting` | どちらの道でも Context を作れなかった（Android 16 の差）。この行と、その前の `context: route … failed` の行を記録する |
| `the app … is not visible to the package manager` | アプリが入っていない、または見えない |
| `handoff: provider not found` | アプリの Provider が見つからない（アプリが入っていない、入れ直しの途中） |
| `handoff: the provider does not belong to the app (provider uid=…, app uid=…)` | Provider の持ち主の uid が、手伝い役が起動のときに覚えたアプリの uid と違う（アプリを消してから入れ直して、uid が変わった）。続けて `exit: アプリが入れ直されたらしい（…）` と出て、手伝い役は**自分で終わる**。手順 7 をやり直す |
| `handoff: the owner of the provider could not be read` | Provider の持ち主の uid を読めなかった。持ち主は分からないので、手伝い役は終わらず、やり直す。続けて出るなら、この行を記録する |
| `handoff: register failed: …` | アプリの Provider を呼べなかった。この行の例外の名前を記録する |
| `register refused for now: …` | アプリが今は受けられない（準備中など）。手伝い役が自分でやり直す |
| `register refused for good: 版が合わない` | アプリが入れ直されて、版が違う。手伝い役は自分で終わる。手順 7 をやり直す |
| `register: not connected yet (failed tries: N, next try in X s)` | まだつながっていない。つなぎ直しは、最初はすぐ。失敗したら2秒後（`failed tries: 1`）、そのあとは5秒おき（`failed tries: 2` 以降）にやり直している |
| `the app is gone; the helper stays and tries to reach it again` | アプリのプロセスが落ちた。手伝い役は残って、つなぎ直す |
| `exit: アプリにつながらないまま 10 分たった` | 10分つながらなかったので、手伝い役が自分で終わった。手順 7 をやり直す |

ログに電話番号や名前は出ません。出ていたら、貼らずに知らせてください。

### 6-4. 手伝い役が起動しないとき（起動そのものを調べる）

手順 7 のスクリプトは、エラーの表示を捨てます。起動そのものを調べるときは、次の2つを実行します。

アプリの APK の場所が分かるか：`package:/data/app/…/base.apk` と1行出れば OK です。

```bash
adb shell pm path io.github.incallagent.rotep
```

エラーの表示を出して、前面で起動する（Java の例外などが PC に出ます。Ctrl+C で止めると、手伝い役も終わります）：

```bash
adb shell sh /data/local/tmp/rotep-helper.sh fg
```

出た文は、そのまま記録します（電話番号や名前は出ません）。

## 7. 終わったら

- 手伝い役が残っていないことを確かめます（手順 15、17）
- 電話の画面のマイクのミュートを戻したことを確かめます
- 使い終わったら、USB デバッグを切ります

## 9. PC なしの起動（ワイヤレスデバッグ）

PC の代わりに、アプリ自身がスマホの adbd（127.0.0.1 だけ）につないで、手伝い役を起動します（ADR-041）。起動の中身は [helper/rotep-helper.sh](helper/rotep-helper.sh) の本文そのもの（PC と同じ）で、起動した手伝い役の扱いも同じです（「終了」で終わる、アプリを入れ直すと自分で終わる、など）。PC の手順は予備として残します。

### 9-1. 必要なこと

- 端末が **Wi-Fi につながっている** こと（ワイヤレスデバッグは Wi-Fi のときだけ使えます）
- 「開発者向けオプション」が有効になっていること（ビルド番号を 7 回タップ）
- 通知を許可すること（ペアリングのコードは通知に入れます）
- 長く使うなら、開発者向けオプションの「**ADB 認証のタイムアウトを無効化**」をオンにします。オフのままだと、7 日間つながなかったときに、端末がアプリの鍵を外します（そのときはペアリングをやり直します）

### 9-2. 最初の 1 回：ペアリング

1. 診断の画面を開き、「PC なしの起動」の **「ペアリングを始める」** を押します。通知の許可を聞かれたら許可します（通知がないとコードを入れられません）
2. 「開発者向けオプションを開く」から、**「ワイヤレス デバッグ」をオン** にします。「このネットワークで許可」を聞かれたら「常に許可」にチェックを入れて許可します
3. 「ワイヤレス デバッグ」の項目を押して中に入り、**「ペア設定コードによるデバイスのペア設定」** を押します。6 桁のコードと IP アドレスとポートの画面が出ます。**この画面を閉じません**
4. 通知を開くと、数秒で「6 桁のコードを入れてください」に変わります。入力欄にコードを入れて送ります（設定の画面に戻るとペアリングの窓が閉じるので、通知から入れます）
5. 「ペアリングできました」と出たら終わりです。設定の「ペア設定済みのデバイス」に `AITEL` が出ます

ペアリングは 1 回で済みます（鍵が端末に残ります）。

### 9-3. 手伝い役の起動（毎回）

ワイヤレスデバッグをオンにして、「PC なしの起動」の **「手伝い役を起動」** を押します。数秒で「手伝い役が動き始めました」と出て、「2. 手伝い役の状態」が「動いている」になります。

### 9-4. 全自動の許可（最初の 1 回）

全自動の電話（時間を指定した電話など）を使うときは、**「全自動を許可」** を押します（PC の `appops set` と同じ。a4.md）。「全自動の許可が入りました」と出れば、再起動しても残ります。

### 9-5. 手で入れるとき（予備）

mDNS でポートが見つからないときや、通知が使えないときは、「手で入れる」の欄を使います。ペアリングは、コードの画面の「IP アドレスとポート」のポートとコードを入れて「この値でペアリング」を押します（通知が使えないときは、画面分割でアプリを横に出します。設定の画面を閉じないため）。起動と許可は、ワイヤレスデバッグの画面のポートを入れて押します。ポートの欄が空なら自動で探します。

### 9-6. うまくいかないとき

出来事の欄とログ（タグ `RotepAdb`）を見ます。コードや鍵はログに出ません。

| 表示 | 見当 | すること |
| --- | --- | --- |
| ペアリングの窓が見つからない（「探しています」のまま） | 「ペア設定コード」の画面を開いていない。または mDNS が届かない | 画面を開く。だめならポートとコードを手で入れる（9-5） |
| 「コードが違うか、時間切れです」 | コードの打ち間違い、または窓が閉じた（設定を閉じた） | 通知からもう一度入れる。窓が閉じたときは、設定で新しいコードを出して入れる（通知の入力欄は新しい窓が開くと戻ります） |
| 「この端末にアプリの鍵が登録されていません」 | ペアリングがまだか、7 日で外された、「ペア設定済みのデバイス」から消した。鍵を断られても、アプリは別のポートを探し直し、3 回続けて断られたときだけ、ペアリングが外れたと見なす | 9-2 をやり直す |
| 「ワイヤレスデバッグのポートにつなげません」「ポートが見つかりません」 | ワイヤレスデバッグがオフ、または Wi-Fi が切れた。鍵の問題ではないので、**ペアリングのやり直しは要らない**。前のポートの記録に当たっただけなら、アプリが数秒で探し直す（出来事に「ポート A につなぎます」「ポート B につなぎます」と続けて出る） | ワイヤレスデバッグをオンにして、Wi-Fi を確かめる |
| 「15 秒たっても手伝い役がつながりません」 | 起動の行は通ったが手伝い役がアプリにつながらない | 6-3 の順でログを見る（`RotepHelper`） |

### 9-7. 再起動とアプリの更新のあと

- **再起動のあと**：「PC なしの起動」でペアリングしてあれば、Wi-Fi につながったところでアプリが自分で手伝い役を起動します（「再起動のあと、Wi-Fi につながったら自動で起動する」のスイッチ。既定はオン）。ワイヤレスデバッグは再起動でオフに戻るので、アプリが「手伝い役を起動」のときに同じ接続でもらった `WRITE_SECURE_SETTINGS` の権限（`pm grant`。スイッチをオフにすると `pm revoke` で取り消します）で入れ直します。起動の直後は Android の順番待ちで、1〜2 分かかることがあります
- 自動の起動が通らないときは通知で知らせます：「このネットワークでの許可が要ります」（画面の確認で「常に許可」を選んで「起動」を押す）、「手伝い役を起動してください」（ワイヤレスデバッグをオンにして「起動」を押す）、「もう一度ペアリングしてください」（鍵を断られたとき）、「Wi-Fi を待っています」（Wi-Fi が来たら自動で起動）。ポートが見つからないなど、少し待てば通りそうな失敗は、1 分、3 分、10 分のあとに、アプリが最大 3 回やり直します（通知は「手伝い役の起動をやり直します」。単体テストだけで、実際の端末では確かめていません）
- **アプリの更新のあと**：「手伝い役を起動し直してください」と通知します。上のスイッチがオンなら、Wi-Fi につながっているときにアプリが自分で起動して、通知が「手伝い役を起動しました」に変わります。オフのときは、「起動」を押すか、診断の画面から起動します
- **手伝い役が消えたとき**：アプリが動いている間に手伝い役が消えると、「手伝い役が止まりました」と通知します。上のスイッチがオンで、USB デバッグかワイヤレスデバッグがオンのときは、アプリが自分で起動し直します。Wi-Fi が切れているときは、Wi-Fi が戻ってから起動します。続けて消えるときは 10 分に 1 回までです。Wi-Fi につながったまま両方がオフのときは、本人が切ったとみなして起動し直しません（銀行のアプリのためなど）。そのときや、スイッチがオフのときは、「起動」で起動し直します
- 更新のあとと手伝い役が消えたときの自動の起動は、Android 16 のエミュレータで確かめました。スマホでは、まだ確かめていません。どちらも、ワイヤレスデバッグがオフなら、アプリがオンにしてから起動します
- 「開発者向けオプションを普段は切っておく」がオンのときは、ここに書いた自動の起動はしません。電話の前に起動します（11 節）
- **指定した時刻の電話**：再起動や更新で予約が消えていたら、通知で知らせます（アプリを開かなくても）

手伝い役の寿命についての注意（AOSP のソースから分かることです。USB デバッグがオンならワイヤレスデバッグをオフにしても手伝い役が残ることと、Wi-Fi が切れたあとも動くことは、スマホで確かめました。USB デバッグも切ったときは、まだ確かめていません）：`adbd` が止まると、`adbd` から起動した手伝い役も一緒に終わります。USB デバッグもワイヤレスデバッグもオフになると `adbd` は止まります。Wi-Fi が切れてもワイヤレスデバッグだけが切れて、USB デバッグがオンなら `adbd` は動き続けます。だから **USB デバッグはオンのままにします**（ただし銀行のアプリの中には、USB デバッグがオンだと起動しないものがあります。そのときは 11 節の形を使えます）。最初の準備の案内は、診断の画面の「案内」から開きます。

## 10. お店からの折り返しの通知（ADR-047）

AI が前に電話したお店から着信があったときに、「前に電話した〇〇からの着信かもしれません（〇月〇日の予約の件）」と通知が出ることを、協力者に電話してもらって確かめます。**電話は人がかけます**（相手は協力者だけです）。端末ではまだ確かめていません。Nothing OS で着信の番号が見えるか、ロールを頼めるかは未確認です。Android 16 のエミュレーターでは、シミュレートの着信（照合だけ偽物に差し替え）で、確認の画面、鳴り方が変わらないこと、通知、ロック中に出ないこと、オフのときは何もしないことを確かめてあります。

### 10-1. 用意するもの

- 設定の「電話の記録」をオンにしておくこと（既定でオンです）。オフのときの電話は記録に入らないので、通知は出ません
- 協力者 2 人（A、B）。**A と B の番号を端末の連絡先から外しておきます**（連絡先に入っている番号は、Android がこのアプリに見せません。消すのが嫌なら、連絡先に入っていない番号でかけてもらいます）
- 協力者の発信は、番号を通知する状態にしておきます

### 10-2. オンにする

1. 設定の「お店からの折り返し」で「お店からの折り返しを知らせる」をオンにします
2. 端末の確認の画面が出たら、「アイてる!?」を選びます。**ほかの発信者番号・迷惑電話のアプリを選んでいると、そちらは外れます**（端末で 1 つだけです）。終わったら戻すので、前に選んでいたアプリを控えておきます
3. スイッチがオンのままで、赤い文字が出ていないことを確かめます

### 10-3. 記録を作る

1. 協力者 A に、アプリから電話します（「電話をかける」。ふつうの試験通話と同じ手順です）
2. 結果の画面まで進めて、記録に入ったことを確かめます

### 10-4. 折り返してもらう

| # | 端末の状態 | やってもらうこと | 期待すること |
| --- | --- | --- | --- |
| 1 | ロックを解除して、画面を見ている | A からかける | いつもどおり鳴る（音が増えない）。通知の一覧（画面の上から引き下ろす）に店名と日付が出る。鳴っている間は着信の表示が上に出るので、ポップアップは見えないことがある。出ても切れない。終わったら着信履歴に残っている |
| 2 | ロック中（画面を消す） | A からかける | 着信の画面はいつもどおり。**ロック中の画面に、店名も内容も出ない**。切ったあと、ロックを解除すると通知の一覧に出ている |
| 3 | ロックを解除している | 通知を押す | アプリが開く。通知は消える |
| 4 | ロックを解除している | B からかける（記録にない番号） | いつもどおり鳴る。通知は出ない |
| 5 | ロックを解除している | A が番号を通知しないでかける（先頭に 184） | いつもどおり鳴る。通知は出ない |
| 6 | 設定をオフにする | A からかける | いつもどおり鳴る。通知は出ない。確かめたらオンに戻す |
| 7 | 再起動のあと、アプリを開かない | A からかける | 1 と同じ（アプリが動いていなくても通知が出る）。アプリの起動の分だけ、鳴り始めが少し遅れることはある |
| 8 | 任意：A に AI で電話している間 | B からかける | AI の通話が切れない。通話の相手に通知の音が入らない。B が記録にあれば、通知はポップアップなしで一覧にだけ出る |

### 10-5. 通知が出ないとき

PC をつないで、次のログを見ます。ログに番号は出ません。

```bash
adb logcat -d -s Rotep/callback
```

- 何も出ない：このアプリに着信が届いていません。番号が連絡先に入っている、端末の設定でこのアプリが選ばれていない、Nothing OS が呼んでいない、のどれかです
- `call: incoming=true number=false`：端末が番号を渡していません（非通知か、Nothing OS の制限）
- `call: incoming=true number=true` のあとに `found=false`：記録に、その番号がありません
- `found=true` なのに通知が出ない：このアプリの通知が許可されているかを確かめます

### 10-6. 終わったら

- 結果を手元に残します（番号は書き写さない）
- 前に使っていた迷惑電話のアプリがあれば、端末の設定の「デフォルトのアプリ」で戻します。使わないときは、設定のスイッチをオフにします
- 端末で通らないときは、`CallbackFeature.ENABLED` を `false` にすると、設定の項目ごと隠れます

## 11. 開発者向けオプションを普段は切っておく（ADR-049）

普段は開発者向けオプションを切っておいて、電話の間だけアプリが USB デバッグをオンにすることを、スマホで確かめます。**電話は人がかけます**（相手は協力者だけです）。Android 16 のエミュレーターでは確かめてあります。Nothing OS で同じように動くかは、未確認です。

### 11-1. 用意する

1. 9 節の手順で、ペアリングと手伝い役の起動を 1 回済ませます（「再起動のあと、Wi-Fi につながったら自動で起動する」はオンのまま）。ワイヤレスデバッグの確認は「常に許可」を選びます
2. 「設定」の「開発者向けオプション」で「開発者向けオプションを普段は切っておく」をオンにします。押せないときは、スイッチの下の文のとおりにします
3. 診断の画面の「終了」で手伝い役を止めます

### 11-2. 合格の条件（Nothing OS で見てほしいこと）

| # | やること | 期待すること |
| --- | --- | --- |
| 1 | スマホの設定で、開発者向けオプションを切る | 主スイッチがオフになる |
| 2 | いつも起動しない銀行のアプリを開く | 起動する |
| 3 | 診断の画面の「電話の準備を試す」を押す | 出来事に「手伝い役が動きました（N 秒）」「元に戻しました（USB デバッグ：オフ、ワイヤレスデバッグ：オフ）」と出る。**主スイッチがオフのまま動くかが、一番の確かめどころです** |
| 4 | 協力者への依頼を「承認して電話する」 | 「電話の準備をしています」と出て、十数秒で発信する。確認の画面の「電話のしかた」に「電話の間だけ USB デバッグをオンにします」と出ている |
| 5 | 話してもらう | ふだんどおり話せる（AI の声が届く、相手の声が取れる）。電話の間ずっと手伝い役が動いている |
| 6 | 電話を終えて、銀行のアプリを開く | 数秒で手伝い役が止まり、銀行のアプリが起動する |

### 11-3. ほかの電話の入り口

| # | やること | 期待すること |
| --- | --- | --- |
| 1 | 時間を指定した電話を、2 分以上先の時刻で承認して、スマホをロックする | 時刻に電話がかかる（ロックしたままで）。終わると元に戻る |
| 2 | Muse か Grok からの依頼を承認する（すぐの電話、`call_at` の電話） | 同じように動く |
| 3 | Wi-Fi を切って、時間を指定した電話を待つ | 電話はかからず、「Wi-Fi につながっていなかったので、電話をかけませんでした」の通知が出る。ほかの AI にも同じ文が届く |

### 11-4. 途中で何かあったとき

| # | やること | 期待すること |
| --- | --- | --- |
| 1 | 電話の途中で Wi-Fi を切る | 電話は続く（手伝い役が残る）。終わると元に戻る |
| 2 | 電話の途中でスマホを再起動する | 起動のあと、USB デバッグがオフに戻っている |
| 3 | 「常に許可」にしていない Wi-Fi で「電話の準備を試す」を押す | 確認の画面が出て、「この Wi-Fi が「常に許可」になっていなかったので…」と出る |
| 4 | 「電話の準備をしています」の間に「やめる」を押す | 電話はかからず、元に戻る |

### 11-5. うまくいかないとき

ログ（タグ `RotepAdb`）に `before a call: 結果`、`debugging switches are as they were` が出ます。番号は出ません。

```bash
adb logcat -d -s RotepAdb
```

切り捨てるときは `AdbFeatures.ON_DEMAND` を `false` にします。スイッチもボタンも隠れて、今までの動きに戻ります。
